# バグ調査・修正記録

## 進め方と既存変更の保全

要求された `agent-desk-bug-triage` は、このセッションでは未登録で読み込めず、プロジェクト内にも手順ファイルが見つからなかった。代わりに要求された段階（範囲別の調査のみ → リーダーによる再現・根拠の監査と採否判断 → 採用候補の修正委託 → 回帰確認）で実施した。

調査は送信・再接続、履歴・添付ファイル、更新・設定保存の3担当に分けた。修正は担当ごとの非重複ファイルに限定し、既存の端末質問UI・関連文書・ロックファイルの未コミット差分には手を加えていない。既存の変更は今回のコミットにも含めない。実モデル・外部モデルAPI・本番データは使用せず、一時データ、模擬応答、ローカルHTTP/WebSocketで検証した。

## 採用して修正した候補

### S1: 保存後に失敗した設定反映が、同じ値の再送で回復しない

- 根拠: `createSettingsService` は保存・公開後に反映する。反映失敗後の再送では保存済み設定との値比較が一致し、実行用設定の更新や再起動が行われない。サブエージェントの無効設定が保存されても、実行用設定は有効のまま残る再現をリーダー側でも確認した。
- 修正: `server/settings.js` で保存済みの未完反映をサービス内に保持し、次の `settings.update` の保存成功後、最新設定を使って再試行する。部分反映後や再起動失敗後の再起動要否も保持する。保存失敗時には新たな反映を登録しない。
- 動作・制約: 保存済みエラーの通知は維持する。原因解消後に同じ設定を再送するか、別の設定を更新すると未完の反映を再試行する。時間ベースの自動再試行ではない。未完情報はプロセス内のみで、内部 `mutate` 独自の反映処理やバックグラウンド取得の再試行方針は変更しない。
- 回帰: `test/settings.test.js`。同値再送、回復後の不要な再起動防止、キューと最新値、保存失敗、部分反映、再起動失敗を検査。修正前の対象6試験で5失敗を確認後、関連96試験が成功した。

### D1: 初回接続・再接続の古い hello が、新しい設定を巻き戻す

- 根拠: `fullState` が設定を取得した後で `accounts()` を待つ間に、新設定のイベントが先に配信される。実 `createSocketServer` とローカルWebSocketで `settings(true) → hello(false)` を再現した。実storeを使う模擬ブラウザでも、非表示タブの通知欠落をリーダー側で確認した。スナップショット収集後のmicrotask競合も再現した。
- 修正: `server/index.js` から既存の設定getterを `server/websocket.js` に渡し、helloのJSON化・送信と同じ同期区間でsettingsだけを最新化する。元のスナップショットは変更しない。
- 制約: settings以外のフィールドの同期を一般的に保証する変更ではない。全イベントの保留・再生は、古い状態で巻き戻す危険を避けるため行わない。
- 回帰: `test/websocket-hello.test.js` と `test/store-sharing.test.js`。修正前の実WebSocket3試験で2失敗を確認。修正後は初回・再接続・microtask・元オブジェクトの非変更・既存呼び出しとの互換性・通知を含む関連35試験が成功した。

### F1: 行範囲付きのファイル参照が解決されない

- 根拠: 実在する `src/a.ts:42` と `src/a.ts#L42-L50` は解決されるが、`src/a.ts:42-50` は存在しない扱いになり、回答からファイルを開けない。既存のFileRef → file.stat → resolveReference経路と、行番号付きパスの対応を確認した。
- 修正: `server/file-refs.js` の行番号除去用正規表現1行を修正。`:開始行-終了行` も既存形式と同様にファイルを解決する。行範囲選択UIなどの新機能は追加しない。
- 回帰: `test/file-refs.test.js` の追加2試験は修正前に失敗、修正後は既存11試験と合わせ13試験すべて成功。入れ子・絶対・装飾付きパス、既存形式、literal優先、UNC拒否を検査し、関連42試験も成功した。

## 保留・不採用

| 候補 | 判断と理由 |
| --- | --- |
| 送信RPCタイムアウト後に手動確認待ちになる | 現行文書が手動確認を明記しており、仕様違反と判断できない。挙動の再現はしたが修正しない。 |
| `::$DATA` による実行ファイル拡張子判定の迂回 | 判定の迂回は確認したが、実際の起動経路では失敗して誤起動しなかった。実害未確認のため防御強化を追加しない。 |
| 64 MiB超の会話の検索除外 | 実際の会話での到達・影響を未再現。修正しない。 |
| 履歴の切り出し・添付名の切り詰めによるサロゲートペア切断 | 利用者影響を未再現。修正しない。 |
| 実行ファイル名末尾のドット・空白による起動、チェックポイントの大小文字のみの改名復元 | 実行確認で正常に処理され、不具合ではなかった。 |
| インストール済み依存と監査済みロックの不整合 | 全体試験で判明。MCPクライアント2.2.0がロック指定2.3.0と不一致。Zodもインストール済み4.6.5が指定4.6.6と不一致で、配列検証とMCPの307/308リダイレクト拒否にも失敗。今回変更したコードを経由しない依存関係の試験であり、既存ロックの未コミット変更や稼働中の依存環境を保全するため、依存更新・再インストールは実施しない。安全性の検証が通っていない未解決事項として報告する。 |
