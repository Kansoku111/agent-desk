# AIから会話履歴を検索する

[← 機能の詳細](features.md)

## 使い方

「設定 → 一般 → 会話履歴の検索」をオンにして、通常のdshタスクで依頼します。既定はオフです。

> このプロジェクトの過去の会話を検索して、繰り返している作業や指示から役立つSkillsを3つ提案して。根拠の会話も示して。まだ作成はしないで。

全体を振り返るときは「全プロジェクトの過去の会話から」と依頼します。特定の期間や、ユーザーの指示だけを対象にすることもできます。検索は空白区切りのキーワードによるAND部分一致で、意味検索ではありません。

## オン・オフの反映

- オフでは履歴用MCPを新しい実行環境に登録せず、検索・取得ツールの定義も渡しません。
- 切り替え後、作業中のdshターンがすべて終了した時点で既存の仕組みにより実行環境を更新します。既存タスクも次回の送信・再開で反映します。
- オフにした直後から、残っているツール経由の検索・取得も拒否します。すでに会話へ返した抜粋は消えません。進行中のモデルリクエストに渡したツール定義は、その場では取り消せません。
- この設定は履歴ツールの提供を切り替えるもので、ファイル操作ツールから履歴ファイルを読むことまで禁止するアクセス制御ではありません。

## 対象

検索対象は、アプリが登録・保存しているユーザーの発言とAIの回答です。

- 通常のdshタスク、TM・eco・ABがdshタスクとして保存した会話。
- アプリに登録されたClaude Codeタスクの会話。画面の直近80ターン制限にかかわらず、元の会話ファイルに残っている発言を検索します。アプリに未登録のClaude Codeセッションを一括収集することはしません。
- チームのClaude Code子の保存済み会話（保持されている最大60ターン）。失われた古い会話は復元しません。

ツール自体は通常のdshタスクと、既存の追加MCPが許可されるdsh担当に提供します。Claude CodeのターミナルやABの相談・判断担当、追加ツールを使わないチームの子には追加しません。ただし、それらの保存済み会話を通常タスクから検索することはできます。

思考、ツールの引数・出力、添付画像、認証設定は結果に含めません。アーカイブ済み会話も対象ですが、削除済みタスクは対象外です。巻き戻されたdshターンはその印を付けて返します。会話は現在の指示ではなく資料として扱うようツールに明記し、Skill提案には参照元のセッションID・メッセージ番号を使うよう案内します。古い指示や却下案を採用すべきかの判断はAIが行うため、保証ではありません。

## トークンとデータ

- 検索処理はローカルで実行し、別のモデルを呼びません。バックグラウンドの学習・自動巡回・Skill作成は行いません。
- オンの間は2つのツール定義がモデルへ渡るため、その分の入力トークンは増えます。検索・取得した文章も、そのタスクのモデルへ送られ、通常の入力トークンを使います。過去の発言には個人情報が含まれる場合があります。
- 検索は既定5件・最大20件、抜粋は1件320文字まで。本文は1メッセージずつ既定4,000文字・最大12,000文字で取得し、続きを必要時に読みます。
- 検索の既定範囲は現在のプロジェクトです。別のプロジェクト、または全プロジェクトも指定できます。この範囲指定は検索の絞り込みで、セキュリティ境界ではありません。
- 日付はUTCの開始日・終了日を含みます。ページング中や取得前に元の会話が変わると、結果の位置も変わり得ます。
- 読めない・壊れた・64MiB超のJSON会話ファイルは検索時に飛ばし、件数を返します。Claude Codeの壊れた行や8Mi文字超の行も飛ばして件数を返します。検索ページが途中で終わる場合、件数はそのページまでの走査範囲です。本文取得時に読めなければエラーにします。
- 新しい履歴コピーや検索インデックスは作らず、元の会話・保存形式・設定済みモデル・課金経路を変更しません。

## 実装の判断

履歴の常時注入やベクトルDBではなく、任意のMCPを使うローカル検索と部分取得に分けています。普段のプロンプトを増やさず、既存の保存データと実行環境更新を利用するためです。実装は `server/history.js` と `server/history-mcp.js` です。
