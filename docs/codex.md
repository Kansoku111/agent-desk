# Codex（GP）

[← README](../README.md)

プロジェクト行の **GP** は、同梱の公式 Codex を使う新しいタスクを作ります。CLの右にあります。通常のGPTタスクは従来どおりdsh＋公式SIWCで動き、GPとは実行方式・会話履歴・認証・利用枠が別です。

## 接続と使い方

1. PCの「設定 → アカウント → Codex（GP・画像生成）」でサインインします。画像生成用に接続済みなら追加のサインインは不要です。
2. プロジェクト行のGPを押し、チャット欄に依頼を送ります。
3. Codexが利用できるモデル・推論レベルと、読み取り専用／ワークスペース編集／フルアクセスを選べます。作業中は設定を変更できません。

通常GPで最後に選んだモデル・推論レベル・権限は、GP専用の既定値としてプロジェクト共通で記憶します。フルアクセスを選ぶと次の新規GPもフルアクセスで始まります。サーバーに保存するため、アプリ再起動後やスマホからの作成でも引き継ぎます。初回の設定がない場合だけCodexの既定モデルとワークスペース編集を使います。既存タスクの設定は変更せず、TM・eco・ABの担当設定や通常GPT／CLの既定値とも混ぜません。

モデル名と推論レベルをまとめたボタンを押すと、左に利用可能な全モデル、右に選択モデルの対応レベルを表示します。候補が多い場合は一覧内をスクロールできます。両方を選ぶか、外側を押すとまとめて反映します。ボタンのモデル名・推論レベルの上ではホイールでも切り替えられます。モデルを変えて今のレベルが使えない場合は、そのモデルが返す既定レベルを使います。

選んだ推論レベルは、各ターンの指定に加えて、新しい会話の作成時にもCodexの会話そのものの推論レベルとして渡します。ターンの指定だけでは会話の履歴内更新として弱くしか効かず、`max` が `medium` から `high` 程度の軽さで動いていました（同じ25問で、ターンだけ `max` は29〜71秒・推論0〜2.3k、会話にも `max` を渡すと142秒・推論6.4k。経緯は `docs/investigations/gpt-siwc-regression-20261107.md`）。そのため、これ以降に作る会話では `high` 以上は従来より時間とトークンを使います。軽くしたいときは推論レベルを下げてください。会話の推論レベルは会話そのものには保存されないため、送信のたびに選択中のレベルを渡します。サーバーが会話を読み込んだままだと再開時の指定が無視され、変更が弱くしか効かない（下げたレベルが元の高いまま動くことも含む）ので、再開の応答が報告するレベルが選択と違うときは、会話を一度手放してから再開し直してレベルを会話に反映します。履歴は保たれ、新しい会話は要りません。変更後の最初の送信だけ、履歴を全部送り直すため少し時間がかかります。反映を確認できないときは、別のレベルで動かさずエラーにします。

権限は現在の権限名を表示する小さなボタンから選びます。押すと3つの候補が開き、選ぶと反映します。スマホでもモデル選択と同じコンパクトな表示です。

回答、コマンド出力、ファイル変更、承認をチャットで表示します。作業中の送信は追加指示です。停止はCodexの中断完了を待ちます。スマホからも送信・承認できますが、サインイン操作はPCで行います。

Codexの逆質問ツールは、質問カードに選択肢と説明を表示します。各質問の選択肢を選び、自由記述が許可された質問は入力もできます。すべて回答して「回答を送信」を押すとCodexへ返します。「スキップ」は未回答として閉じます。読み取り専用でも質問には回答できます。質問待ちはメモリ上で管理し、再起動後に古い質問を再送しません。秘密入力は伏字にし、Agent Deskの画面用履歴には回答を追記しません。TM・ecoの子とAB担当は対話待ちにせず、従来どおり親や各ワークフローへ判断を返します。

ワークスペース編集はCodexのサンドボックス内で実行し、追加権限が必要な場合は承認カードを出します。読み取り専用は権限昇格を許可しません。フルアクセスはファイルシステムの制限がないため、信頼できる依頼にだけ使ってください。

## サブエージェント

Codex自身の `multi_agent` は無効にしていますが、同梱のCodex 0.167.0はgpt-6系のモデルに独自のサブエージェントツール（`spawn_agent` など）を設定とは無関係に渡し、「サブエージェントを呼んで」と頼まれたモデルは、MCPツールよりそちらを選びました（`gpt-6-luna`・`low`で確認）。設定では無効にできなかったため、仲介ツールをマウントしたタスクには「Codex自身のサブエージェントは使わず、`subagent` を呼ぶ」という開発者向けの指示を毎回加えています。指示による誘導なので、モデルが従わなければ設定の委託先は使われません。代わりに、GPタスクには仲介ツール `subagent`（MCPサーバー名 `agent-desk-subagent`）が常に加わり、「設定 → モデル → サブエージェント」のGPの行が指す先で子が動きます（既定はCodex。モデルを指定しなければ、そのGPタスクのモデルと推論レベルです）。この呼び出しはCodexの承認カードを出さず、そのまま実行します（利用者が設定で選んだ機能のためです）。GPの親のMCP設定は、メッセージを送るたびに設定へ合わせて更新します。

Codexの子は、親と同じ作業フォルダ・同じ権限モードの無人のセッションです。人への質問や承認を出せないため、コマンドやファイル変更の承認が必要な操作は拒否されます。Windowsで読み取り専用やワークスペース編集のサンドボックスがコマンドを実行できない環境では、子も読み取りに失敗します。そのような環境では、親をフルアクセスにしてください。子のセッションはタスク一覧と通知に出ず、完了後に削除します。Agent Deskの終了で残った子は、次の起動時に削除します。

## 履歴と互換性

- 履歴、ピン留め、アーカイブ、コピー、削除はGPタスクとして管理します。
- アプリ再起動時の未完了ターンは中断として表示し、自動で再送しません。履歴と実ファイルを確認してから再開してください。
- 再開先の会話IDが一致しない場合、新規会話や別の実行方式へ切り替えず停止します。
- サインイン先が変わった既存タスクは、新しいタスクの作成を案内します。Codexが公開するメールアドレス・ワークスペース名から作る照合用ハッシュのみをタスクへ保存し、その値を画面へ返しません。Codexが照合できる識別情報を返さない場合、既存会話の再開は拒否します。
- 通常GPの「開く」から[子に委託・独立レビュー](task-presets.md)を使えます。GP自身が指示を作り、選んだ別担当が作業します。dsh用のPTC切替、ゴール制御、チェックポイント復元、観測者、実行方式をまたぐ自動フォールバックはGPには適用しません。通常GPTやCLの設定は移行・変更しません。
- 作業用Codexではネイティブの多重エージェント、ゴール、フック、プラグインなどを無効にし、アプリ所有のワークフローと競合させません。

## TM・eco・AB

- TMではCodexをリーダーと子の両方に選べます。親にはチーム用MCPを渡し、子の報告を同じ会話へ配送します。子は通常タスクの一覧には出さず、チームパネルから開きます。
- Codexの子を起動するとき、モデル一覧が未取得なら取得してから保存済みの選択を確認します。現在のアカウントにモデルがない場合は起動せず、その理由を表示します。
- ecoでも親・子に選べます。調査は読み取り専用、実装・検証中の書き込みは既存の排他制御を使います。調査した子を実装へ移す場合は同じ会話を維持し、実行権限を明示的に変更します。
- ABでは相談・判断・実装・レビューに選べます。実装以外は読み取り専用、実装は人間の明示承認後だけです。相談ツール制限がオンの担当とecoの調査担当では、Web検索・シェルとネットワークも制限します。
- 子・AB担当の追加権限要求は拒否し、実行されなかった操作を報告します。担当の設定やecoの判定を通常GPのRPCから迂回できません。
- CodexをTM・ecoの親にしたとき、およびCodexへの親の切り替えは自動フォールバックの対象外です。既存のGPT・CLをCodexへ無断で移行しません。
- 観測者自身の実行方式としてCodexは選べません。既存の観測者がCodex担当を参照する場合も、チームの操作制限を適用します。

## 保存と実行の境界

ユーザーのPATH上のCodexや通常の `~/.codex` は使いません。同梱版は `server/codex-app-server.js` の `CODEX_VERSION` で固定します。更新が必要な場合は[更新手順](updating.md)に従います。

- `codex-home`：Codexが管理する認証と会話。画像用と作業用は認証を共有しますが、別プロセス・別の起動設定で動きます。
- `codex-home/work-state`：作業用の永続DB・診断情報。画像用の一時データ削除の対象にしません。
- `codex-tasks.json` と `codex-tasks/`：Agent Deskが管理するタスク索引と画面用履歴。

画像生成は引き続き読み取り専用・シェル無効の専用プロセスです。GPを追加しても画像用の権限は広げません。UIのタスク削除はCodex自身の会話や共通認証を削除しません。

## 出力速度

GPも生成中と回答後に推定速度を「≈ … t/s」で表示します。本文・表示される思考のストリーミング文字数から推定し、ツール出力・差分・過去の履歴は数えません。ツール実行や承認待ちでは非表示にし、新しい本文・思考ブロックから測り直します。完了後は、最後の応答が計測できた場合だけその受信速度を保存します。最後の応答が短い・一括で届いた等で計測不能なら、以前の応答の値は代用しません。

受信の時間幅が1秒未満、または先頭の塊を除く推定トークン数が25未満なら表示しません。通信のまとめ送りやトークン分割による誤差があり、モデル本体の厳密な生成性能ではありません。Codexのターン全体の使用量を応答単位の速度へ流用しません。

## 使用量

Codexの通知にあるトークン数からAPI料金換算を表示します。実際の請求額・サブスク利用枠の消費を表すものではありません。使用量や単価が不明な分は未算定とし、ゼロ扱いしません。通知が欠けたターンを次のターンへまとめて計上しません。Codexの利用上限とSIWCのアプリ別使用枠も合算しません。

1ターンに複数のモデル応答がある場合、長文の段階料金は応答ごとの入力長で判定して合算します。途中の使用量通知が欠けた場合、確認できた応答だけを算定し、不明分を未算定として表示します。リクエスト回数も、確定できなければ「不明」または確認できた回数以上と表示します。

修正前に保存されたGPの換算額と、それを含む同じタスクの累計は自動では再計算しません。保存された旧換算値には応答別の単価が残っておらず、現在の単価で過去額を置き換えないためです。旧記録には段階料金の誤差が残る場合があるため、保存値は保持したまま、GPの会話画面ではAPI換算額とリクエスト回数を不明として表示します。過去のチームやABの合算画面には旧値が残る場合があります。修正後の分だけを比較するには、新しいGPタスクを使ってください。
