# dsh のアップデート

[← README に戻る](../README.md)

「設定 → 情報」の「dsh のアップデート」で、更新の確認と更新ができます。

- **更新チャネル:** dsh の npm 配布タグから選びます。`latest`（既定）、`next`、`alpha` の3つです。`alpha` を選ぶと、より安定したタグに新しい版があればそちらも対象になります。今より古い版に戻すことはありません。
- **更新の流れ:**
  1. 作業中のタスクが終わるのを待ち、dsh の実行環境を止めます。更新中は新しいメッセージを送れません。
  2. `package.json`、`package-lock.json`、`dsh-home` を、データフォルダの `dsh-update-backup` にバックアップします。
  3. `@deepseek-ai/dsh` と `@deepseek-ai/dsh-atomic-write` を同じ版でインストールします（`npm install --save-exact`）。
  4. 別のプロセスで独自フック（高速モード・割り込み・再試行・ゴール継続）の互換性と合成結果を検証した後、新しい dsh を起動します（`scripts/check-dsh.mjs`）。ACP の接続、セッションの作成、モデル一覧の取得、モデルの選択も確かめます。必要なフックが適用できない版は、起動できても更新を受理しません。
  5. 成功したら、アプリのサーバーを再起動します。開いているウィンドウは自動で再接続します。
- **失敗したとき:** インストールか動作確認で失敗したら、バックアップの `package.json` / `package-lock.json` を戻して `npm ci` で旧版を復元します。新しい dsh が `dsh-home` に手を加えた可能性があれば、それも独立して元に戻します。失敗した版は記録され、自動更新では入れ直しません（手動では再試行できます）。
- **復旧にも失敗したとき:** 新しいタスクの実行を停止し、再起動後もその状態を保持します。ネットワーク・空き容量・ファイルのロックなどの原因を解消してから、「設定 → 情報 → 復旧を再試行」を押してください。アプリ自体が起動しない場合の手順は、バックアップ内の `RECOVERY.md` にあります。`dsh-update.json` を手動で消して実行制限を解除しないでください。
- **自動で更新する:** 既定はオフです。dsh は互換性を壊す変更が多いため、オンにする場合も動作確認と自動の巻き戻しが前提です。
- **動作確認の範囲:** フックの適合性・構文・主要な接続契約と、起動・セッション作成・モデル選択を確認します。モデルへの実際のリクエストやツールの実行は行わないため、すべての動作を保証するものではありません。
- **記録:** 更新の状態は `dsh-update.json` に、更新の記録はサーバーのログと `launcher.log` に残ります。どちらもデータフォルダにあります。
