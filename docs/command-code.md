# Command Code Provider API

[← README に戻る](../README.md)

## 接続

「設定 → アカウント → Command Code」で、本人の Command Code Studio で発行した API キーを保存します。モデル一覧から **Command Code** または **Command Code（Claude）** のモデルを選びます。通常タスクのほか、チームのリーダー・子や対応するワークフローでも接続先を明示して選べます。既存の接続先やタスクは変更しません。

[公式 Provider API](https://commandcode.ai/docs/provider) を使います。GOAT など API 対応プランが必要で、**Go プランは Provider API 非対応**です。公式 CLI のログイン情報や非公開 API は使用しません。プランとキーの有効性は公開モデル一覧から確認できず、最初のモデル呼び出しまで未確認です。別の人の認証情報を使ったり、利用制限を回避したりせず、[利用規約](https://commandcode.ai/terms)と自分の契約に従ってください。

公式の公開モデル一覧は全プラン共通で、一覧に出ても自分のプランで使えないモデルがあります。契約対象を確認して明示的にモデルを選んでください。未選択時には Command Code のモデルを自動選択しません。最新の[プランとモデル](https://commandcode.ai/docs/resources/pricing-limits)を確認してください。

「設定 → 情報 → 更新」の Command Code 行で取得・反映の状態を確認できます。右上の「今すぐ確認」とアカウント欄の「モデル一覧を更新」は、自動同期がオフでも一覧を再取得します。作業中は実行環境を中断せず「一覧の反映待ち」と表示し、作業終了後に反映します。他の接続先の更新では、確認済みの推論候補を維持します。候補が欠けていて Command Code の実行環境が適用済みなら、作業中でも別セッションで候補を再確認します。dsh の更新や接続方式の変更時は、安全のため再確認まで候補を表示しません。取得に失敗した場合は警告し、最後に取得した一覧を使います。反映に失敗した場合は「今すぐ確認」で再試行できます。自動同期がオンなら起動後と定期的にも取得します。

## 料金とデータ

Command Code の利用は登録したキーの契約・クレジット・利用上限に従います。追加クレジットや自動チャージにより、サブスクリプション料金以外の支払いが発生する場合があります。並列実行にも注意し、利用状況と実際の請求は Command Code の Studio で確認してください。Agent Desk は厳密な支出上限を強制せず、Command Code の実請求額や残り枠は表示しません。

モデルへの依頼、会話、モデルが読んだファイルやツール結果は Command Code およびその処理先へ送信されます。設定で「ゼロデータ保持（ZDR）」をオンにすると、対応する公式ヘッダーを付けます。作業中の dsh がすべて待機状態になって実行環境が更新されてから反映され、ZDR 対応の処理先がないモデルはエラーになります。利用条件・料金への影響は[公式説明](https://commandcode.ai/docs/provider)を確認してください。ZDR は Agent Desk のローカル会話履歴を削除しません。

## 接続方式と制約

公開一覧の対応エンドポイントに基づき、Chat Completions と Anthropic Messages の2経路を分け、どちらも同じ Command Code API キーを使います。Claude モデルは Anthropic API 直契約や Claude Code の認証には切り替わりません。通常タスクでは画像対応が確認できる `deepseek/deepseek-v4.1-flash` と `deepseek/deepseek-v4-flash-vision-exp` を画像入力可能として登録します。それ以外はテキストのみです。モデル一覧に画像対応情報がないため、この対応範囲はアプリ更新時に見直します。API での実際の画像利用可否は契約や処理先にも依存します。画像は Command Code とその処理先へ送信されます。画像付きABやチーム観測者は別の制限があります。出力上限は Command Code のモデル一覧で値が提供されればそれを優先し、なければ [OpenCode の公開モデル情報](https://models.opencode.ai/api.json)から取得します。取得できないときは最後に保存した値か同梱済みの値を使います。モデルIDが一致する場合だけ適用し、どちらにも上限情報がないモデルは 8,192 トークンです。会話と自動圧縮の余地を残すため、コンテキスト長に応じて上限を調整します。推論も出力枠を消費するため、上限を増やすと利用量や処理時間が増える場合があります。[API 換算額の単価と制約](usage.md#回答末尾の累計api換算額)は実請求とは別です。

推論レベルは、同梱した [Command Code 公式 CLI のモデル定義](../server/command-code-efforts.json)を基に選択できます。例外として Ling 3.1 Flash 1019 は [別サービス向けの第三者スキーマ](https://modelschemas.com/models/vercel/vercel-inclusionai-ling-3-1-flash-1019)を参考に low・medium・high を選べますが、Command Code の Provider API で各レベルが反映されるかは未確認です。定義にないモデルや、レベル指定がないモデルは「指定不可」のままです。モデル一覧の自動同期ではこの推論定義は更新されず、アプリの更新で追従します。「既定」は推論レベルを指定せず処理先の既定に従います。CLI にある「オフ」は Provider API で無効化できることを確認できないため表示しません。Claude 互換経路では [Anthropic の API 仕様](https://platform.claude.com/docs/en/build-with-claude/effort)も考慮します。対応状況や選択したレベルの実際の効果は処理先によって異なる場合があります。

モデル一覧の取得にはキーや会話を送らず、公式一覧から ID・表示名・コンテキスト長・対応形式だけを検証し、`command-code-models.json` に保存します。未対応形式は除外し、日付付きの正規 ID は省略せず表示します。キーは他の API キーと同じ `dsh-home/.credentials.yaml` に保存し、既存のローカル LLM 設定は使いません。
