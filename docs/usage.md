# 使用量の表示

[← README に戻る](../README.md)

## 回答末尾の累計API換算額

既存の入力・出力トークン表示の先頭に、**API料金換算の累計額（USD／JPY）**を`API換算 $19.2`のように表示します。小さいほど換算上の消費が少ない指標で、品質の点数・実際の支払額・サブスクリプションの利用枠ではありません。従来のptの保存形式は維持し、**1 pt = $0.002** の固定倍率をUSD基準にするため、過去分の再採点やデータ移行はしません。

**設定 → 一般 → 回答末尾のAPI換算額**でUSD／JPYを選び、JPYでは「1 USD = 何円」を入力して保存します。初期状態はUSD・レート未設定で、正の有限値を保存するまでJPYには切り替わりません。為替の自動取得や外部通信は追加しません。例えば元のUSD換算額が$19.282996、150円/USDなら、USD表示は`$19.2`、JPY表示は`¥2,892.4`です。レートを変えると過去分も同じレートで円表示が変わりますが、元の使用量とUSD換算額は変わりません。設定は全画面へ反映され、モデルの再起動は不要です。

- **通常:** タスクの全ターン累計。モデル変更や会話の引き継ぎでも、それまでの消費を残します。
- **Eco・TM:** 親の最新回答は親＋全担当の累計。子の個別画面はその子の累計です。差し戻し、再試行、`fresh`前の会話、削除した子の取得済み消費も残します。
- **AB:** 最新の判断・実装・レビュー報告は、相談A・B、指示作成、実装、レビュー、追加相談、失敗と再試行を含むAB全体の累計です。個別報告はその担当分です。

入力・出力・キャッシュ読み書きはモデルごとの単価で計算し、長文の段階料金は応答ごとに判定してから合算します。GPT・Claude・OpenCode Goは既存のpi-ai／同梱・取得済み追加カタログ、DeepSeekは既存の公式料金定義を使います。料金を調べるためのモデル呼び出しや、新たな料金同期サービスは追加しません。カタログの反映時に新モデルの単価も取り込みますが、カタログ自体の不足・更新遅れはあり得ます。独自モデルやアカウント一覧から複製した仮定義に、元モデルの単価を流用しません。

Claude Codeの親は保存済み会話ログ、非対話の担当は`stream-json`の応答から集計します。同じ応答の複数ブロックは重複加算しません。CLIが報告した5分／1時間キャッシュ作成の内訳と速度を使用し、dsh側の高速設定はCLIへ誤適用しません。[Anthropicのキャッシュ料金](https://platform.claude.com/docs/en/build-with-claude/prompt-caching#pricing)では1時間の作成は通常入力の2倍です。TTL内訳を取得できないdshログは既存の5分作成単価を使います。非対話CLIの応答別使用量がなければ、取得できたCLIの推定費用を換算します。

**料金または使用量が不明な部分はゼロ扱いにしません。** 全部不明なら`API換算 —`、算定済み分と未算定が混在すれば`API換算 ≥ $…`／`API換算 ≥ ¥…`を表示します。API換算額は選択通貨で小数点以下最大1桁の切り捨て表示（$19.282996 → `$19.2`）にし、不要な末尾のゼロは省きます。既知の正の値が0.1未満なら`< $0.1`／`< ¥0.1`、既知のゼロは`$0`／`¥0`で区別します。一部未算定の下限額も切り捨てて過大に表示しません。保存済みの計算値や手動レートの精度は落としません。dshの応答に使用量がなくても未算定として数え、同じ集計範囲内に同一応答の使用量記録があれば重複なく補完します。通常のClaude Code自身が`Agent`等や別モデルのMCPへ委託した分は、別ログの使用量を取得していないため未算定です（Agent Deskが管理するTM・Eco・ABの担当は合算対象です）。旧版の履歴で換算値を記録していない分も未算定になり得ます。

換算値は初回算定時に保存し、料金カタログの更新で確定済みの過去分を再計算しません。実行中・応答記録が未取得の消費を含む厳密な支出上限ではなく、取得できたモデル使用量を比較するための概算です。横の入力・出力は従来どおりそのターン分、先頭のAPI換算額は累計です。金額をクリック・タップ、またはキーボードでフォーカスしてEnterを押すと詳細が開きます。Escapeで閉じると元のボタンへ戻ります。JPYでは適用した手動レートとUSD基準額も確認できます。ターン別・セッション累計の従量課金概算や設定画面の請求額は元のUSD表示を保ち、円換算の参考額や実際のカード支払額と混ぜません。換算値のない旧履歴も、保存済みの従量課金概算は詳細から確認できます。

## 設定画面の使用量

「設定 → 使用量」には、出どころの違う2つの数字を並べます。

- **Agent Desk での使用量（概算）:**
  - すべてのタスクの応答を dsh のセッション記録（`dsh-home/sessions`）から集計し、Claude と DeepSeek の API 料金を見積もります。追加の設定は要りません。
  - Claude はモデル一覧の単価を使います。DeepSeek は [公式料金表](https://api-docs.deepseek.com/quick_start/pricing/)の入力・キャッシュ・出力単価を使い、応答記録の時刻でピーク／オフピークを判定します。単価の確認日と対応モデル、中国の祝日日程は `server/deepseek-pricing.json` に記録します。未登録年の祝日は割引を推定せず、平日のピーク時間には高い方の単価を使います。
  - DeepSeek の過去の回答も、トークン数が保存され、対応するセッション記録が残っていれば開いたときに料金を補完します。料金改定前の記録も保存済みの単価で見積もるため、実際の請求額と異なる場合があります。正確な請求額は各社の管理画面で確認してください。
  - 削除したタスクの分も含みます。集計結果はログごとに `usage-history.json` に保存し、変わったログだけを読み直します。旧版でサブスクの換算額が混入したキャッシュは、次回の集計で換算額だけを除去します。トークン数・従量課金分・削除済みログの履歴は保持します。
  - 課金モデルの単価が不明ならゼロ扱いにせず、全額不明は `—`、一部不明は算定済みの下限 `≥ $…` を表示します。旧キャッシュは残存ログを一度読み直し、削除済みログの記録も保持します。ただし、削除済みログの旧集計に算定済み・未算定が混在していた場合、その内訳は復元できません。
  - 通常タスクのターン別集計は、直下のサブエージェントだけでなく、その子が委託した分も同じ時間範囲で合算します。
  - 日付はパソコンの時刻（ローカル時刻）で区切ります。
  - ChatGPT・OpenCode Goのサブスクリプションなど、従量課金でない経路はこの料金集計へ含めません。トークン数は集計し、回答末尾のAPI料金換算額とは区別します。
- **Claude の請求額（実額）:**
  - Anthropic の Usage & Cost API から取得します。Claude Console の「Cost」と同じ数字で、Agent Desk 以外での利用も含みます。
  - この API は Admin API キー（`sk-ant-admin…`）か、ワークスペースを限定しない個人キー・サービスアカウントキーでしか読めません。登録済みの Claude の API キーで読めなければ、画面から Admin API キーを登録します。
  - Admin API キーは組織の管理者だけが作成でき、個人アカウントでは使えません。キーは `dsh-home/.credentials.yaml` に保存されます（dsh はこのキーを使いません）。
  - 初回に過去1年分を取得して `claude-cost.json` に保存し、以後は直近の数日分だけを取り直します。日付は UTC 基準で、利用から反映まで数分かかります。
