# エコモード（eco）

[← README に戻る](../README.md)

プロジェクトの **eco**（TMの左）から始めます。既存のTMとは別のモードで、TMの保存済み設定は変更しません。

## 使い方

1. 親と子のモデルを選びます。親にはClaude CodeのOpus／Sonnet、またはカタログにあるClaude API／GPTを使えます。子はHaiku級など、用途に合った低価格モデルを選んでください。親・子の実行方式とモデルは選択した時点でアプリ側に保存し、開始せずに閉じた場合や開始に失敗した場合も次回に引き継ぎます。同じアプリに接続するPC・スマホ間でも共通です。従来のブラウザ内だけの選択はアプリ側に未保存の場合に一度移行します。キー削除・非表示・提供終了などで使えないモデルは「モデルを選択」に戻し、再選択するまで開始しません。別のモデルや課金経路には自動で切り替えません。
   モデルの隣で親・子の推論レベルを独立に選べます。「既定」は未指定です。推論値もアプリ側に保存し、再表示・再起動後に復元します。モデル／プロバイダー変更で無効になった値は既定へ戻し、旧データの未指定値も既定として扱います。API／サブスクリプションモデルはカタログが示す値、Claude Codeは既存のCLI用選択肢を使います。保存中に開始しても最新の選択の保存完了を待ち、親と子のそれぞれの起動へ値を渡します。開始済みecoには遡及しません。
2. プロジェクトの検証コマンドを登録します。例：`npm test`、`npm run build`。ID、実行場所、制限時間を設定できます。
3. 「始める」を押し、親に依頼します。親が完了条件と使う検証を選び、子へ委託します。

```text
親：方針・完了条件
  → 子：調査・実装
  → アプリ：検証・限定的な差し戻し
  → 親：結果と根拠をまとめて判定
```

検証設定はプロジェクトごとに保存します。開始後も、エコモードのパネルにある「検証設定」で変更できます。既に委託した作業は委託時の検証定義を使い、後の設定変更では置き換わりません。親は必要なときだけタスク専用の追加検証も指定できます。

## 実行と判定

- **2段構成：** 親と子の低枠だけを使用します。中位モデルへの自動昇格や、別課金経路への自動切り替えはしません。
- **書き込みは直列：** 実装、検証、親の判定が終わるまで、次の書き込み担当は開始できません。同じフォルダとその中の別タスクの開始・入力・復元も制限します。上位フォルダ（My PCなど）のタスクは止めず、書き換えは検証の「古い」判定で検出します。
- **調査は並列：** 親は `mode: research` の調査専用の子を起動できます。dshの子は読み取り専用で、権限変更・昇格を許しません。Claude Codeの調査専用の子はRead／Glob／Grepだけを使い、シェル・編集・MCPは使いません。
- **アプリが検証：** 子の最終報告を受けて、選ばれたコマンドを順に実行します。コマンド、実行場所、終了コード、時間、ログ、ソースの状態を保存します。WindowsではPowerShell 7（`pwsh`）、その他では`/bin/sh`を使います。
- **差し戻し：** 「失敗時に子へ自動差し戻し」を明示した検証だけが対象です。最大2回（親は0〜2回で指定可能）。同じ失敗の繰り返し、認証・課金・通信系と判別できたエラー、タイムアウト、対象の変更、キャンセルは親へ戻します。失敗の分類はエラー文による判定なので、環境に応じた完全な分類を保証するものではありません。
- **報告：** 実行と検証を一つの報告にまとめます。他の子が作業中の間は成功報告を最大30秒だけ集約し、エラー・停止・承認待ちは先に返します。調査専用の子の報告は検証せず、読んで `close` するだけです。待機中に親を呼び続けたり、キャッシュ維持だけの呼び出しをしたりしません。
- **判定：** 親が完了条件と差分を確認して合格にします。検証に失敗した結果や、検証後にソースが変わった結果は合格にできません。検証コマンドを使わない作業は「未実行」とし、親自身が確認した根拠を残して合格にします。中止は合格とは別に記録します。
- **停止と再起動：** 「全停止」は実行中の子だけでなく検証も止め、自動差し戻しを止めます。再起動で中断された検証を成功扱いにはしません。

## 状態記録の範囲と注意

Gitプロジェクトでは、追跡ファイルとGitで除外されていない未追跡ファイルの内容をハッシュ化します。コミットIDや差分だけの比較ではありません。未追跡ファイルの追加・削除も検出します。サブモジュールは、そのフォルダを別のプロジェクトとして開いてください。

Git未使用のフォルダも使えます。この場合は `.git`、`node_modules`、`.venv`、`venv`、`__pycache__`、`dist`、`build`、`coverage`、`.cache` のディレクトリを除き、ファイルを記録します。除外ファイル、外部依存、外部サービスの状態まで固定する仕組みではありません。

検証中はソースの変更を監視し、判定時にも内容を再確認します。外部エディタや、アプリの管理外で動くプロセスをOSレベルで禁止する機能ではありません。親には、子の作業中・検証中の編集を禁止し、判定待ちで全ての子が待機中の場合だけ範囲内の小さな修正を許可します。親が編集したら `verify` で再検証し、新しい結果を待って判定します。バックグラウンドの書き込み処理は残さないでください。

**コマンドの終了コードが0でも、依頼が正しく完了したとは限りません。** 必要な検証の選定と仕様の確認は親が行います。検証コマンドはこのPCのユーザー権限で動くため、削除・デプロイ・外部接続などの副作用があるコマンドを無条件に登録しないでください。フォーマッタなど意図的にソースを変える検証だけ、「ソース変更と1回の再検証を許可」（`allowSourceChanges`、初期値オフ）を設定できます。許可した検証の実行中だけ変更が検出され、全コマンドが成功した場合に限り、アプリが1回だけ再検証します。通常の検証や検証間での変更、監視エラーは親へ返します。変更したプロセスの特定はできないため、許可した検証中の外部編集まで区別できる保証はありません。再検証の報告と結果JSONには初回記録への参照・初回と再実行の対象状態が残り、親は変更差分も確認します。親が自分でファイルを直したときは `verify` で子を動かさずに再検証できます。

Claude Codeの認証・課金確認はTMと同じ仕組みを使用します。APIモデルは従量課金です。利用枠の消費や節約率をAPI料金比から断定せず、厳密な金額上限も保証しません。

## 記録と初版の範囲

アプリのデータフォルダ内の `teams/execution/projects.json` に検証設定、`teams/execution/runs/<ID>/` に検証のJSONとログを保存します。`teams.json` に完了条件、判定、差し戻し回数、親子のターン数、報告・検証回数を記録します。dshが返した使用量は取得できた範囲で保存し、取得できないものは不明のままです。Claude Codeの子はターン終了時のトークン数と推定費用も記録します。Claude Code CLIの親はトークン数を取得できず、ターン数は受信したプロンプトフックに基づきます。

確認役の子の自動追加、検証候補の自動調査、worktreeによる書き込み並列化、TMとの消費比較画面は初版には含みません。
