設計上の決定
既存 dsh の汎用接続を再利用する。初期のチーム構成は「クラウドのリーダー ＋ 権限を制限したローカルの子」。独自の推論エンジンやモデル管理機能は作らない。

ねらい

  • Ollama、LM Studio、llama.cpp、vLLM などの推論サーバーを利用可能にする。
  • モデル名ではなく、API 互換性・能力・実行制限で扱う。
  • 既存の会話、権限管理、ツール、履歴、変更の巻き戻しを再利用する。

対応範囲

初期対応OpenAI 互換 Chat Completions、接続先とモデルの登録、一覧取得／手入力、通常タスク、チームのローカルの子、共有推論キュー
後続対応ローカルのリーダー、チーム設定の全面汎用化、文章専用の子、同一 GPU のリソースグループ
初期対象外モデルのダウンロード、GPU 管理、推論サーバーの起動管理、ツール非対応モデルの専用チャット

「OpenAI 互換」は完全な互換性を意味しない。サーバーごとの設定と実機検証を行い、すべてのモデルの自律作業を保証するものにはしない。

ARCHITECTURE

接続とモデルを分離する

Agent Desk の画面・通常タスク・チーム
↓
dsh ／ pi-ai の任意プロバイダー経路
↓
Agent Desk 内の推論ゲートウェイ
共有キュー・接続先専用の認証・ストリーム中継
↓
ユーザーが起動した推論サーバー → モデル

通信方式は openai-completions を初期標準とする。既存 dsh の providers 設定へ任意の経路を追加し、独自 LLM アダプターは初期段階で作らない。

設定単位保持する情報
接続先安定した内部 ID、表示名、API 種別、URL、専用キー（任意）、互換性設定、タイムアウト、同時実行数
モデル接続先 ID、API に渡すモデル ID、表示名、有効コンテキスト長、最大出力、ツール・画像・推論設定の確認状態

API 差異を接続設定で吸収

store、developer ロール、max_tokens、ストリームの使用量情報などは互換性設定で調整する。サーバー名はプリセットとして扱い、モデル名による分岐は避ける。

無認証サーバー向けにも、現行 pi-ai が要求するキー相当の指定を補完する。クラウド用の認証情報は流用しない。中継口はループバック限定・アプリ認証付きとし、任意 URL へ転送できる汎用プロキシにはしない。

モデル ID と設定反映

内部参照は [provider, modelId] のペアに統一。ローカル用の検証では / や : を許容し、制御文字と過大な長さを拒否する。モデル ID は原則として元のまま転送する。

設定変更の即時反映は未検証。実行中タスクを壊さない反映方式を優先し、必要なら安全なタイミングでランタイムを再起動する。

TEAMS & EXECUTION

チーム連携と実行の安全性

チームは小さく拡張してから汎用化

既存のチーム設定へ local 枠を追加し、低枠・中枠ごとに接続先とモデルを指定する。既存の設定・モデル選択・履歴を維持し、自動で有効化しない。後続段階で各枠を「実行方式 ＋ 接続先 ＋ モデル」の共通構造へ移行する。

項目初期方針
リーダー既存の GPT または Claude Code。ローカルのリーダーは後続対応。
ローカルの子ツール呼び出しの往復を確認したモデルを使用。リーダーへ結果を報告し、追加指示では同じ会話を再利用。
権限調査は読み取り専用、編集はワークスペース内書き込み。権限外の操作はリーダーへ承認を中継。フルアクセスは明示的に有効化。
ツール作業に必要なものへ限定。子からの再委任は既存どおり無効。能力テストは安全性の保証には使わない。

共有キューは「推論1回」単位

  • 接続先の同時推論は初期値1。通常タスク・チーム・履歴要約で共有する。
  • タスク全体では枠を確保しない。ツール実行や子の報告待ちには枠を保持しない。
  • 待機中のキャンセル、生成中の切断、エラー時の解放を一元管理する。
  • 待機時間と生成のタイムアウトを分ける。再試行による重複と待ち続ける要求を防ぐ。

コンテキスト長は実際の設定を基準にする

サーバーの一覧情報は初期候補とし、設定値を確認・修正できるようにする。最大出力に加え、指示・ツール定義・履歴が収まる余地を確保する。小さい容量ではツール削減と履歴圧縮を検証し、実測せずに固定の最小容量は断定しない。

混成チームのデータ経路
クラウドのリーダーへローカルの子の報告が渡る。子の推論がローカルでも、チーム全体が外部送信なしになるわけではない。

DELIVERY & VALIDATION

段階導入と完了条件

段階実施内容次へ進む条件
0接続検証実機でツール往復、ストリーム、モデル ID、初回プロンプト量、履歴圧縮を確認。設定反映方式を決定。
1通常タスク接続・モデル設定、一覧／手入力、動的カタログ、能力確認と選択可否、エラー表示が動く。既存経路も維持。
2推論ゲートウェイ複数ランタイムでも並列上限を守る。待機・生成の中断、切断、再試行、要約で枠が漏れない。
3チームの子クラウドのリーダーから起動・報告・再指示が可能。権限と承認、停止・再開、保存・復元を確認。
4後続拡張外部モデル不使用モード、設定構造の汎用化、ローカルのリーダー等を個別に検証して導入。

主な変更箇所

dsh-config.js：経路・設定生成 ／ catalog.js：動的プロバイダー
settings.js・モデル関連 RPC：保存と検証 ／ ゲートウェイ：新規
team-config.js・teams.js・team-mcp.js・teams-prompts.js：枠・起動・権限・指示 ／ Web UI：設定と選択

外部送信を止める範囲を明示する

外部モデル不使用モードは許可リスト方式とし、クラウドへの自動切替を禁止する。検索・画像生成・クラウドの子に加え、更新確認・使用量取得などの補助通信も対象を棚卸しする。

これは OS 全体の通信遮断ではない。シェル、Web 取得、MCP などの通信まで止める場合は、別途ファイアウォールやネットワーク分離が必要。「完全ローカル＝外部通信ゼロ」とは表記しない。
