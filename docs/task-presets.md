# 通常タスクのプリセット

[← 機能の詳細](features.md)

通常のdshタスク／Claude Codeタスク／GP（Codex）タスクの右上「開く」から、**子に委託**と**独立レビュー**を開始できます。TM・eco・ABやチームの担当を変換する機能ではありません。GPは親として使い、担当モデルは開始画面で選びます。

## モデルの選択

開始画面でモデルと推論レベルを直接選びます。選択はその都度保存され、キャンセル後や再起動後も、委託とレビューそれぞれの最後の選択を使います。「設定 → モデル → タスクのプリセット」からも変更できます。未設定または利用できないモデルでは起動できません。以前のレビュー設定だけがある場合は、元タスクがClaude CodeならDSH、それ以外ならClaude Codeの設定を初期表示し、選択すると共通のレビュー設定に保存します。別の実行方式へ自動で切り替えません。既存の系列別サブエージェント、TM・eco・ABの設定とは独立しています。

## 子に委託

1. 元タスクで方針を相談し、待機中になってから「開く → 子に委託」を選びます。
2. 担当・推論・権限を確認し、必要な追加指示を入れて「始める」を押します。
3. **元セッションの現在のモデルが**、目的・対象／非対象・合意済み方針・完了条件・検証を短い指示へまとめます。重要な未決事項があれば担当を起動せず質問を表示します。
4. アプリが設定済みモデルの新しい会話を起動し、実装・制作・調査など依頼された実作業と、その結果の確認まで担当させます。必要なスキル・参照先・成果物を指示に残し、絵の依頼をコード実装へ置き換えません。会話全文の複製や、孫への再委託は行いません。

この操作は実作業の委託で、担当は既定で実装・制作まで行い、細かな不明点は自分で判断して進めます。過去のモデル自身が「今回は相談のみ・構想だけ」と宣言していても、それを利用者が指定した制約とは扱いません。**利用者の指示・意向は最優先です。** 利用者自身が相談のみ・調査のみと明示した場合はその通りに依頼し、重大な未決事項も維持します。

## 独立レビュー

開始画面でモデル・推論レベルと方法を選び、権限を確認して始めます。方法の初期状態は「意見を聞く」です。

- **意見を聞く**：設計案、相談中の問題、実装などについて、ファイルを変更せず独自の意見・懸念・代替案を報告します。
- **レビューして修正**：担当は懸念を仮説として扱い、発生条件・具体的な影響と根拠を確かめた範囲内の問題を修正します。修正後は、その問題の解消と関連する回帰を確認します。根拠が不足する懸念や未実施の確認は未確認として報告し、安全に再現できない重大な問題は危険な再現をせず根拠を報告するよう指示します。必要な確認が済んだら改善点を探し続けず終了し、問題がなければ変更ゼロで終了できます。利用者が明示した制約は優先されます。これらは担当への指示であり、アプリが根拠や確認の実施を保証するものではありません。

元セッションのモデルが、会話から対象・背景・要件を判断して短い依頼を作ります。意見を聞く場合、検討中の設計案も評価対象として渡しますが、親の推論過程や既存レビューの結論は複製しません。会話全文をforkせず、対象を判断できない場合は質問します。対象を変えたいときは元の会話で伝えてから始めてください。Gitのないフォルダーでも使えます。

担当は別の新しい会話で作業し、右サイドのカードから様子を見られます。修正担当による未対応指摘や検証失敗は同じ担当へ戻し、具体的な障害や進捗のない反復は「要確認」とします。修正を別モデルが再レビューする機能ではありません。

元タスクのモデル、およびそのタスクで完了した「子に委託」の担当と同じ選択値は拒否します。GPの親と、同じモデルIDの通常GPT担当も別モデルとは扱いません。通常タスクの過去のモデル履歴やClaude Codeの別名の解決までは復元しないため、別モデルを使いたい場合は担当設定も確認してください。

## 完了と親への返送

**「意見を聞く」は完了時に結果を親へ自動送信します。** 「子に委託」と「レビューして修正」は手動で返送します。

- 「意見を聞く」が完了すると、結果を親へ一度だけ送り、親が応答します。dshの親にgoalがある場合、自動返送はgoal自体を再開しません。親が作業中・元セッションが変更済みなどで送れなければ結果画面に理由を表示し、自動再送しません。内容を確認したうえで手動返送できます。
- 「子に委託」と「レビューして修正」は、完了表示だけでは親に送信しません。dshの親にgoalがある場合も、次の明示的な入力まで待機させます。
- 元タスクの右サイドに親と担当（モデル・推論レベル・状態）を並べます。TM・ecoの子と同じく、担当のカードを押すとメイン画面に担当の作業がそのまま流れ、「親」のカードで元タスクへ戻れます。パネルは右上の「委託」で開閉でき、狭い画面では初めは閉じています。
- **担当画面の入力欄は通常タスクと同じ使い方です。** 作業中に送ると、いま動いている担当へ割り込みます(次のステップで読みます)。止まった後や完了後に送ると、同じ会話への返信として新しいターンが始まり、モデル・推論・権限は変わりません。Escで作業を止められます。添付と送信待ちの予約はありません。再開の処理中に別の返信を送った場合は、成功扱いにせず再送を案内します。返信の送信自体では親の会話に何も送りません。
- 返信の開始前後でファイルが変わらず結果ブロックも返さなかった場合は、会話だけとして扱い、返信前の状態・報告・送信済みの状態をそのまま残します。未完了の担当への質問も、作業の自動再開にはしません。返信中にファイルが変わったのに結果ブロックが無い場合や、返信開始時の変更確認を取得できない場合は、担当へ報告を求めます。変更確認を取得できなくても返信自体は送信します。新しい結果は検証し直され、「意見を聞く」では自動返送を試み、それ以外は「本セッションに渡す」で送れます。親が作業中でも返信できます。
- 担当画面の「詳細」で、検証結果・差分・報告全文・親の指示を確認できます。差分とログは開いたときに取得し、128KBを超える場合は省略と全文の保存先を示します。
- 手動返送の「本セッションに渡す」を押すと、結果の要約・検証状態・資料参照を元の会話へ送り、親モデルが応答します。同じ結果は自動・手動を合わせて重ねて送信しません。新しい結果は改めて送信できます。親が作業中なら送信せず、待機してから操作し直します。
- 担当を開始できなかった場合や、担当からの報告がまだない場合は「本セッションに渡す」を表示しません。開始エラーを担当の報告として親へ送らず、結果画面に開始状況を表示します。開始前の失敗は元の依頼を確認して「開く」から新しく開始してください。
- Claude Code端末やGPへの結果送信で受理を確認できなかった場合は、重複を避けるため再送しません。元の会話を確認してください。

## 権限・検証・停止

- 独立レビューのDSH担当は「意見を聞く」で読み取り専用です。「レビューして修正」と子に委託するDSH担当は、開始時に作業フォルダーへの書き込みまたはフルアクセスを選べます。既定は作業フォルダーへの書き込みです。Claude Code担当はフルアクセスで動きますが、意見モードでは書き込み・コマンド実行ツールを渡さず、変更しないよう指示します。OSによる読み取り専用の保証ではありません。開始画面で権限と課金経路を確認し、認証方式が変わった場合は再確認が必要です。親の権限は変更しません。
- 委託用MCPを通常セッションへ常設しません。担当への追加MCPも既定ではありません。子に委託では必要な場合だけ「実行設定」でブラウザを有効にできます。通常のサブエージェントをオフにしていても、人が開始するこのプリセットは使えます。
- 子に委託の「実行設定」では、既存のプロジェクト検証や追加コマンドを明示的に選べます。独立レビューの画面にはこの設定はなく、担当自身が必要な確認を行います。**選択したコマンドは担当のサンドボックス外で、PC上のアプリが実行します。** 親モデルのJSONから任意コマンドを自動登録・実行しません。
- 担当内で実行できない登録済み検証だけが残る場合、担当は検証待ちを返し、アプリが選択されたコマンドを実行します。修正が残っている状態での検証待ちは許しません。選択がなければ「コマンド未選択」であり、アプリ検証の成功を意味しません。担当が自分で行った確認は報告・作業記録で確認できます。
- Windowsの作業フォルダー書き込みモードでは、サンドボックスの初期化がアクセス拒否になったり、Nodeのテストランナー等の子プロセス起動が`EPERM`になったりする場合があります。自動昇格はしません。委託なら明示したアプリ側検証を利用するか、委託・レビュー修正の開始画面でフルアクセスを選んで新しく開始できます。フルアクセスでは作業フォルダー外への操作も可能になります。
- 委託中も、同じフォルダーで別の通常タスクを開始できます。親の追加入力・設定変更や、復元、他の委託・チーム作業との競合には制限があります。委託の開始・再開時も、復元や他の委託・チーム作業との競合を確認します。
- 「停止」で担当・検証を止めます。「同じ担当で続ける」は文面を付けない明示的な再開で、モデル・推論・権限を黙って変更しません。アプリ再起動後の途中の実行は「要確認」として復元し、自動ではモデルを動かしません。元タスク削除時も進行中の担当を停止します。

## 大きな作業フォルダー

「子に委託」と「独立レビュー」では、アプリ側の検証コマンドを選んでいなければ、フォルダー全体の変更確認が件数・時間の上限に達しても、記録を取得できない旨を表示して親の指示作成と担当の実作業を続けます。差分保存だけが上限に達した場合も、通常の委託は続けます。作業フォルダー・モデル・権限は勝手に変えません。

記録の未取得は「変更ゼロ」でも「アプリ検証の成功」でもありません。担当自身の成果物・画像確認・実行結果などを報告で確認してください。全体の指紋を取得できない場合、アプリ検証は「コマンド未選択」のままで、指紋を検証済みにしません。

選択済みの検証コマンドを省略することはありません。指示作成の途中で対象を確認できなくなった場合や、権限・読み取り等の別のエラーも引き続き「要確認」です。必要なら対象フォルダーを絞って開始してください。

## 保存と使用量

設定は`settings.json`の`taskPresets`、実行の記録はデータフォルダー内の`task-presets/`、Claude Code担当の会話は`task-preset-agents/`に保存します。元タスクを削除しても保存済みの結果は残します（開いていた結果画面でも確認できます）。既存セッションを移し替えたり削除したりしません。

結果画面のAPI換算額は担当の累計です。親の指示作成と明示的な結果送信の使用量は元タスク側に含まれ、担当の費用をそこへ二重加算しません。不明な使用量はゼロにしません。[使用量の表示](usage.md)。

未使用の通常ターンに追加の委託用ツール定義・指示を載せず、全文forkと不要な親の呼び戻しを避ける設計です。ただし、親が指示を作る1ターンと担当の実作業は必要です。使用後の指示は親の履歴に残り、厳密な節約率やキャッシュヒット、サブスク利用枠の消費率は保証しません。

## 開発時の確認

`node --test test/task-presets*.test.js`はモデルを使わない回帰確認です。読み取り専用の担当を含む実行先の選択と、実際のACPセッションの起動・権限も確認します。PC／390px幅の操作確認は`test/fixtures/task-presets-ui.html`の隔離Reactフィクスチャ（`window.taskPresetsTest.run()`と`window.taskPresetsTest.failures()`）で行えます。

次は実際のモデルを使い、利用枠を消費します。製品コードやユーザーの作業フォルダーは変更せず、使い捨てのコードで確認します。会話記録や信頼済みフォルダー情報はCLIが通常どおり保存します。モデルを変更せず、GPTは`gpt-6-luna`・`low`、Claude Codeは`haiku`・`low`を明示します。Claude Codeはsubscription経路を確認できる場合のみ開始します。

```powershell
node scripts/smoke-task-presets.mjs gpt
node scripts/smoke-task-presets.mjs claude
node scripts/smoke-task-presets.mjs terminal
node scripts/smoke-task-preset-worker.mjs gpt --full-access
node scripts/smoke-task-preset-worker.mjs claude
node scripts/smoke-task-preset-worker.mjs gpt --opinion
```

担当の通常チェックは修正と`node --test`成功まで確認します。`--opinion`は実際の読み取り専用の実行先で問題を報告し、対象ファイルを変更していないことを確認します。GPTの修正例はWindowsのNodeテスト起動を含むため、テストの権限を`--full-access`で明示しています。本番の権限を自動昇格する指定ではありません。[初期調査と判断の記録](investigations/task-action-presets.md)。
