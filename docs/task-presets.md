# 通常タスクのプリセット

[← 機能の詳細](features.md)

通常のdshタスク／Claude Codeタスクの右上「開く」から、**子に委託**と**独立レビュー**を開始できます。TM・eco・ABやチームの担当を変換する機能ではありません。

## 最初の設定

「設定 → モデル → タスクのプリセット」で、2つの担当のモデルと推論レベルを選びます。初期値は未設定です。既存の系列別サブエージェント、TM・eco・ABの設定とは独立し、モデルや課金経路を自動で切り替えません。

## 子に委託

1. 元タスクで方針を相談し、待機中になってから「開く → 子に委託」を選びます。
2. 担当・推論・権限を確認し、必要な追加指示を入れて「始める」を押します。
3. **元セッションの現在のモデルが**、目的・対象／非対象・合意済み方針・完了条件・検証を短い指示へまとめます。重要な未決事項があれば担当を起動せず質問を表示します。
4. アプリが設定済みモデルの新しい会話を起動し、実装・制作・調査など依頼された実作業と、その結果の確認まで担当させます。必要なスキル・参照先・成果物を指示に残し、絵の依頼をコード実装へ置き換えません。会話全文の複製や、孫への再委託は行いません。

この操作は実作業の委託で、担当は既定で実装・制作まで行い、細かな不明点は自分で判断して進めます。過去のモデル自身が「今回は相談のみ・構想だけ」と宣言していても、それを利用者が指定した制約とは扱いません。**利用者の指示・意向は最優先です。** 利用者自身が相談のみ・調査のみと明示した場合はその通りに依頼し、重大な未決事項も維持します。

## 独立レビュー

**指摘の報告だけでは終わらず、同じレビュワーが指摘箇所の修正・検証まで行います。** 修正するかの相談で止まらず、細かな判断はレビュワーが行います。利用者が「指摘の報告だけ」と明示した場合は、その指示が優先されます。

委託と同じく、右サイドのカードを押すとレビュワーの作業がメイン画面に流れます。

こちらも毎回、元セッションの現在のモデルが要件と**レビューの対象**を短い依頼にまとめます。何を見るか（ファイル・変更・機能）は元セッションが会話の内容から決めるため、コミットや範囲を選ぶ操作はなく、Gitのないフォルダーでも使えます。別の新しい会話でレビュー修正担当を開始し、担当は対象の実際の状態を自分で確認します（Gitがあれば履歴も参照できます）。親の推論過程・実装者の完了宣言・既存レビューの結論を初期入力に複製しません。対象を変えたいときは、開始画面の追加指示に書いてください。

問題がなければ、変更ゼロで終了できます。好みだけの整理や新機能追加へは広げません。修正可能な未対応指摘や選択済みの検証失敗は同じ担当へ戻します。具体的な環境・権限・仕様上の障害、同じ状態から進捗がない反復は「要確認」とし、未完了を成功扱いにしません。レビュワー自身が修正したコードを、さらに別モデルが再レビューする機能ではありません。

元タスクのモデル、およびそのタスクで完了した「子に委託」の担当と同じ選択値は拒否します。通常タスクの過去のモデル履歴やClaude Codeの別名の解決までは復元しないため、別モデルを使いたい場合は担当設定も確認してください。

## 完了と親への返送

**完了結果やカードの表示は、親への送信ではありません。**

- 担当が終了したら、その担当の作業を終えます。親の会話への追加・送信や、親モデルの自動呼び戻しは行いません。dshの親にgoalがある場合も、次の明示的な入力まで待機させます。
- 元タスクの右サイドに親と担当（モデル・推論レベル・状態）を並べます。TM・ecoの子と同じく、担当のカードを押すとメイン画面に担当の作業がそのまま流れ、「親」のカードで元タスクへ戻れます。パネルは右上の「委託」で開閉でき、狭い画面では初めは閉じています。
- 担当画面の「詳細」で、検証結果・差分・報告全文・親の指示を確認できます。差分とログは開いたときに取得し、128KBを超える場合は省略と全文の保存先を示します。
- **「本セッションに渡す」だけが通常の送信操作です。押すと結果の要約・検証状態・資料参照を元の会話へ送り、親モデルが応答します。** 同じ結果を重ねて送信しません。「同じ担当で続ける」で再開した後の結果は、改めて1回送信できます。親が作業中なら送信せず、待機してから操作し直します。
- 担当を開始できなかった場合や、担当からの報告がまだない場合は「本セッションに渡す」を表示しません。開始エラーを担当の報告として親へ送らず、結果画面に開始状況を表示します。開始前の失敗は元の依頼を確認して「開く」から新しく開始してください。
- 通常Claude Code端末で送信受理の確認ができなかった場合は、自動で再送しません。元の会話を確認してください。

## 権限・検証・停止

- dshの既定は作業フォルダーへの書き込みです。フルアクセスは開始時に明示的に選択します。親の権限は変更しません。Claude Codeの担当はフルアクセスで動き、開始画面でその権限・課金経路を確認します。認証方式が変わった場合は再確認が必要です。
- 委託用MCPを通常セッションへ常設しません。担当への追加MCPも既定ではありません。必要な場合だけ「実行設定」でブラウザを有効にできます。通常のサブエージェントをオフにしていても、人が開始するこのプリセットは使えます。
- 「実行設定」では、既存のプロジェクト検証を明示的に選択したり、追加コマンドを入力できます。初期状態では選択しません。**選択したコマンドは担当のサンドボックス外で、PC上のアプリが実行します。** 親モデルのJSONから任意コマンドを自動登録・実行しません。
- 担当内で実行できない登録済み検証だけが残る場合、担当は検証待ちを返し、アプリが選択されたコマンドを実行します。修正が残っている状態での検証待ちは許しません。選択がなければ「コマンド未選択」であり、アプリ検証の成功を意味しません。担当が自分で行った確認は報告・作業記録で確認できます。
- Windowsの作業フォルダー書き込みモードでは、Nodeのテストランナー等の子プロセス起動が`EPERM`になる場合があります。自動昇格はしません。明示したアプリ側検証で確認するか、必要な権限を確認して新しい実行を開始してください。
- 同一・上位・配下のフォルダーの書き込み、親の追加入力、モデル設定変更、復元と競合する実行は拒否します。読み取り専用タスクからの復元や、通常TMの担当の起動・停止中も対象です。再開時も同じ排他を確認します。外部エディターの編集をOSレベルで禁止するものではなく、記録とソース指紋で変化を確認します。
- 「停止」で担当・検証を止めます。「同じ担当で続ける」は明示的な再開で、モデル・推論・権限を黙って変更しません。アプリ再起動後の途中の実行は「要確認」として復元し、自動ではモデルを動かしません。元タスク削除時も進行中の担当を停止します。

## 大きな作業フォルダー

「子に委託」と「独立レビュー」では、アプリ側の検証コマンドを選んでいなければ、フォルダー全体の変更確認が件数・時間の上限に達しても、記録を取得できない旨を表示して親の指示作成と担当の実作業を続けます。差分保存だけが上限に達した場合も、通常の委託は続けます。作業フォルダー・モデル・権限は勝手に変えません。

記録の未取得は「変更ゼロ」でも「アプリ検証の成功」でもありません。担当自身の成果物・画像確認・実行結果などを報告で確認してください。全体の指紋を取得できない場合、アプリ検証は「コマンド未選択」のままで、指紋を検証済みにしません。

選択済みの検証コマンドを省略することはありません。指示作成の途中で対象を確認できなくなった場合や、権限・読み取り等の別のエラーも引き続き「要確認」です。必要なら対象フォルダーを絞って開始してください。

## 保存と使用量

設定は`settings.json`の`taskPresets`、実行の記録はデータフォルダー内の`task-presets/`、Claude Code担当の会話は`task-preset-agents/`に保存します。元タスクを削除しても保存済みの結果は残します（開いていた結果画面でも確認できます）。既存セッションを移し替えたり削除したりしません。

結果画面のAPI換算額は担当の累計です。親の指示作成と明示的な結果送信の使用量は元タスク側に含まれ、担当の費用をそこへ二重加算しません。不明な使用量はゼロにしません。[使用量の表示](usage.md)。

未使用の通常ターンに追加の委託用ツール定義・指示を載せず、全文forkと不要な親の呼び戻しを避ける設計です。ただし、親が指示を作る1ターンと担当の実作業は必要です。使用後の指示は親の履歴に残り、厳密な節約率やキャッシュヒット、サブスク利用枠の消費率は保証しません。

## 開発時の確認

`node --test test/task-presets.test.js test/task-presets-panel-ui.test.js`はモデルを使わない回帰確認です。PC／390px幅の操作確認は`test/fixtures/task-presets-ui.html`の隔離Reactフィクスチャ（`window.taskPresetsTest.run()`と`window.taskPresetsTest.failures()`）で行えます。

次は実際のモデルを使い、利用枠を消費します。製品コードやユーザーの作業フォルダーは変更せず、使い捨てのコードで確認します。会話記録や信頼済みフォルダー情報はCLIが通常どおり保存します。モデルを変更せず、GPTは`gpt-6-luna`・`low`、Claude Codeは`haiku`・`low`を明示します。Claude Codeはsubscription経路を確認できる場合のみ開始します。

```powershell
node scripts/smoke-task-presets.mjs gpt
node scripts/smoke-task-presets.mjs claude
node scripts/smoke-task-presets.mjs terminal
node scripts/smoke-task-preset-worker.mjs gpt --full-access
node scripts/smoke-task-preset-worker.mjs claude
```

最後の2つは担当の修正と`node --test`成功まで確認します。GPTの例はWindowsのNodeテスト起動を含むため、テストの権限を`--full-access`で明示しています。本番の権限を自動昇格する指定ではありません。[初期調査と判断の記録](investigations/task-action-presets.md)。
