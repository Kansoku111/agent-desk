# 利用上限時のフォールバック

[← 機能の詳細](features.md)

## 設定

「設定 → モデル → 利用上限時の切り替え」を開き、接続先ごとにモデルと推論レベルを1つずつ選び、優先順に並べて「保存」を押します。Claude Code と Claude（API）は認証・課金方式が違うため別の接続先です。通常のdshタスク・Claude Codeタスクと、TM・eco・ABのリーダーが共通の一覧を使います。上限になった接続先を除き、残った最優先の候補を**一度だけ**試します。候補がなければ停止し、切り替え先の失敗や上限から次の候補へ自動で連鎖しません。無効・未接続などでその候補を使えない場合も、黙って別の候補を選びません。

候補にClaude Codeを含めると、その認証方式と課金の可能性を確認します。CLI起動前にも再確認し、方式が変われば再同意が必要です。Claude（API）・DeepSeekなどは従量課金です。料金や同じ認証方式の別アカウントへの変更は、この確認だけでは保証できません。自分で利用を許可された接続先だけを選び、各サービスの規約・利用枠と支出管理に従ってください。

これまでのTM・eco・ABの個別設定は、初めて共通設定を保存するまでは維持します。各開始画面には実際に使う従来の候補を表示します。共通設定を保存すると新しい実行から切り替わります。候補を空にして保存すると、新しい実行の自動切り替えを無効にします。開始済みのTM・eco・ABは開始時の設定を保持し、共通設定を後から変えても課金経路は変わりません。通常タスクは人が送信した各ターンの開始時に一覧を控えます。旧チームや旧ABの履歴・設定も削除しません。

## 対象と条件

- **明確な利用枠の消尽のみ:** 明示的な利用上限コード・文言を受けたときだけ切り替えます。一般的な429、一時的なレート制限、認証エラーだけでは切り替えません。Claude CodeのStopFailureに判定できる詳細がない場合は停止します。
- **通常dsh:** 人が送信したターンが対象です。dsh同士では、同じタスクで指定モデル・推論レベルの適用を確認してから続きを依頼します。実際に使ったモデルを確認できない場合や、実行中に次のモデルや推論レベルを手動変更した場合は、選択を上書きせず停止します。画像付きの会話は、画像の扱いを確認できない接続先へは切り替えません。ゴール履歴を検知した場合、状態を移せると判断できないため停止します。
- **通常dsh → Claude Code:** 権限を広げないため元のタスクがフルアクセスの場合だけ、新しいClaude Codeタスクに会話の抜粋を渡します。画像・Plan・検知したゴール履歴は自動で引き継がず停止します。元のタスクの送信待ちは移動せず残します。作業中のサブエージェントが確認された場合も停止します。
- **通常Claude Code → dsh:** 直前の依頼をClaude Codeの履歴と照合でき、権限状態が確認でき、裏で作業が残っていない場合に限ります。画像・検知したゴール履歴、Planや不明な権限状態は停止します。引き継ぐ会話は抜粋です。権限を勝手に広げないよう、切り替え先は読み取り専用で始まります。書き込みが必要なら、内容と権限を確認したうえで利用者が変更してください。未送信の入力は元の画面に残り、自動では移りません。
- **TM・eco:** リーダーが対象で、チームにつき一度切り替えます。開始時の一覧を保存し、上限になったリーダーの接続先を除いて選びます。dshの親で実行中に次のモデルや推論レベルを変更した場合や、使用モデルが確認できない場合は停止します。dsh同士では同じタスクを使い、Claude Codeをまたぐ場合は会話の抜粋を新しいリーダーに渡します。過去の画像は渡りません。全停止中は切り替えません。子は自動切り替えせず、上限をリーダーへ報告します。
- **AB:** 判断・実装指示・リーダー直接実装・レビューのリーダー段階が対象です。失敗した段階を一度だけ再試行し、以後のリーダー段階も選ばれた候補を使います。相談A・Bと委託した実装担当は切り替えません。画像付きABの候補はClaude Code・Claude API・ChatGPTの経路に限りますが、個々のモデルやCLI版の画像読解を保証するものではありません。
- **対象外:** タスクプリセットの担当、チームの子、ABの相談・委託担当、モデル自身が起動するサブエージェント、画像生成・Web検索などの固定接続ツールは自動切り替えしません。

切り替えを画面に表示します。Claude Codeをまたぐと元のタスクは閲覧用に残り、新しいタスクから続けます。切り替え途中の終了や送信結果が不明な場合は自動再実行せず、作業状態を確認してください。履歴は抜粋・判定はエラー文に依存し、ゴールやバックグラウンド作業の検知も完全ではありません。既存ファイルや完了が不明な外部操作を繰り返さないよう指示しますが、文脈の完全性や重複防止は保証できません。
