# エージェントチーム

[← README に戻る](../README.md)

サイドバーのプロジェクト（または My PC）の「TM」を押すと、チームを始める画面が開きます。ここで、リーダーを Claude Code（ターミナル）にするか GPT（dsh のタスク）にするか、子に使うモデル、同時に動かせる子の数をそのチーム用に選び、「始める」でリーダーが起動します。子に使う GPT・Claude・Claude（API）・DeepSeek は、初期設定ではすべてオフです。初めてのときは、使うものをオンにしてから始めます（少なくとも一つをオンにすると「始める」を押せます）。2 回目からは前回のチームで選んだ値が入っているので、同じでよければそのまま始められます。リーダーに計画や指示を伝えると、リーダーが作業を分けて子のエージェントに任せ、終わった子から届く報告を確認して、合格（close）か手直し（send）かを決めます。

- **料金:** 子は provider ごとに、支払い方法が違います。Claude のリーダーと Claude の子は Claude Code（ログインしているサブスクリプション）、GPT のリーダーと GPT の子は dsh のタスクとして ChatGPT サブスクリプションで動きます。リーダーも子も GPT にすれば、Claude の上限を使わずにチームを回せます。Claude（API）の子は dsh のタスクとして、Anthropic の API キーで動きます。使った分が API の料金になります（Claude Code のサブスクリプションは使いません）。Claude の Max・Team プランに付く毎月の API クレジットは Claude API に使えるので、その範囲で動かせます（Claude Code には使えません）。Anthropic の API キーを登録するとオンにできます。DeepSeek の子は dsh のタスクとして DeepSeek の API キーで動き、使った分だけ DeepSeek に課金されます（子としてだけ使えます。API キーを登録するとオンにできます）。**Claude Code の子は、サブスクリプション以外では動かしません。** 起動する前に `claude auth status`（モデルには何も頼まない確認）で、どのログインで動くかを確かめます。API キー（環境変数、Claude Code の設定、`apiKeyHelper`）や、クラウド（Bedrock・Vertex・Foundry）で動こうとするときは、起動せずにリーダーに知らせます。確認できなかったときは起動し、起動後の最初の報告で API キーを検出したら止めます（この最後の確認は、最初のリクエストに間に合わないことがあります）。環境変数の `ANTHROPIC_API_KEY`・`ANTHROPIC_AUTH_TOKEN` と、クラウドに切り替える変数は、あらかじめ渡しません。GPT のリーダーが Claude のサブエージェント（`subagent_claude`、API の従量課金）を使い始めたら、Agent Desk がその作業を止めてリーダーに知らせます。Claude（API）の子を使うよう、リーダーに伝えます。
- **モデルの選び方:** リーダーが選ぶのは枠（低・中）と GPT / Claude / Claude（API） / DeepSeek だけです。どの枠でどのモデルを動かすかは、チームを始める画面で決めます。GPT・Claude・Claude（API）・DeepSeek は、初期設定ではすべてオフです。使うものだけをオンにします（チームを始めるにも、動いているチームの設定を保存するにも、少なくとも一つはオンにしておきます）。オンにしたものは、低枠・中枠もそれぞれオフにできます（オンにしたものごとに、少なくとも一方の枠はオンのまま）。オフの枠はリーダーに使わないよう伝えます。同時に動かせる子の数（1〜12、close した子は数えない）もここで決めます。設定はチームごとに保存され、別のチームの設定には影響しません。
- **途中での変更:** 動いているチームでも、チームパネルの「このチームの設定」から、子に使うモデルと同時に動かせる子の数を変えられます。変えた内容はリーダーに伝わり、次に作る子から使われます（すでに動いている子はそのままのモデルで続けます）。リーダーを Claude と GPT で入れ替えることはできません。そのときは新しいチームを始めてください。
- **子はサブエージェントを使わない:** 子は自分で作業し、サブエージェントを起動しません。チームの人数が設定どおりに保たれ、動いているものがすべてチームパネルに出ます。並べて進めたい作業は、リーダーが子を増やして分けます。GPT・Claude（API）・DeepSeek の子は、サブエージェントのツール（`subagent`・`subagent_fork`・`subagent_gpt`・`subagent_claude` など）を外した子専用の dsh（`dsh --patch` で重ねる `team-child.patch.yml`）で動きます。Claude の子は `--disallowedTools` で、サブエージェント（Task）や、ほかのエージェントを動かすツール（Workflow・SendMessage・RemoteTrigger・CronCreate など）を使えなくしています。万一、子がサブエージェントを始めたときは、Agent Desk がその作業を止めてリーダーに知らせます。リーダーは自分のサブエージェントを使えます。
- **Claude の子の動かし方:** Claude の子は画面なしの Claude Code（`claude -p --output-format stream-json`）で動きます。1回の依頼ごとに Claude Code を起動し、同じ会話を再開します。作業の終わり・返答・ツールの実行は Claude Code 自身の出力から読むので、フックや画面の読み取りに頼りません。Claude のリーダーはあなたが話しかける相手なので、これまでどおりターミナルの Claude Code です。リーダーの作業の終わりを知らせるフックが届かなかったときに備えて、報告が待っている間はリーダーの会話記録も確かめます。
- **報告の届き方:** 子が作業を終えると、その報告がリーダーの会話に自動で入力されます。報告は終わった順に1件ずつ届き、リーダーが作業中の間や、誰かが入力欄に書いている間は待ちます。待っている間、リーダーは何もせず眠っているので、利用上限を使いません。長い報告は先頭だけを渡し、全文はリーダーが `read_report` で読みます。あなたが子に直接メッセージを送ったときも、その返答を「追加の報告」としてリーダーに届けます（close した子は除きます）。
- **同じ子への再依頼:** 手直しや、あとからの追加作業（2回目の見直しなど）は、リーダーが `send` で同じ子に送ります。子はそれまでの会話を覚えています。close した子にも、会話を引き継いで渡します。
- **承認:** 子はいつも承認なしで動きます（GPT はフルアクセス、Claude は `bypassPermissions`）。Claude の子では、それでも確認が要る操作は実行せずに飛ばし、報告に「承認が必要なため実行されなかった操作」として並べます。リーダーがその内容を見て判断します。GPT や DeepSeek の子が承認を待って止まったときは、まずリーダーに判断を求めます。リーダーにも決められないときはリーダーがあなたに確認を求め（通知が出ます）、14 分たってもリーダーが決めないときもあなたに知らせます。チームのパネルから直接「許可」「拒否」を押すこともできます。リーダーも承認なしで動かすかどうかは「設定 → エージェントチーム」で選べます。
- **画面:** リーダーには「TM」の印が付きます。子のタスクはサイドバーには出さず、リーダーの右側の「チーム」パネルに、名前・業務・モデル・状態を並べます。押すとその子の作業を開きます。Claude の子の画面では、作業の記録を読めるほか、子に直接メッセージを送ったり、作業を止めたりできます（どちらもリーダーに伝わります）。「図を開く」で、リーダーを上に、子を下に並べた構成図を表示します。作業中の子は光り、待機中や完了した子は薄く表示されます。
- **ツールの読み込み:** 子を動かすためのツール（MCP サーバー `server/team-mcp.js`）は、チームのリーダーにだけ渡します（Claude Code には `--mcp-config` で、GPT のリーダーにはその dsh のタスクの MCP サーバーとして）。GPT のリーダーへの指示文は、この MCP サーバーの instructions としてシステムプロンプトに入るので、会話が要約されても消えません。通常のタスクや CL のタスクには、ツールも指示文も加わりません。
- **GPT のリーダー:** 報告は、リーダーのタスクの作業が終わってからメッセージとして届けます。リーダーのモデルを決めていないときは GPT の中枠のモデルを使います。ChatGPT にサインインしている必要があります。
- **削除:** リーダーを削除すると、子のタスクも一緒に削除します。子だけを削除すると、その子はチームから外れます。
- **変更を戻す:** チームの子のタスクでは「変更を戻す」の保存をしません（同じフォルダで複数の子が同時に作業するため）。
