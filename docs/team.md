# エージェントチーム

[← README に戻る](../README.md)

サイドバーのプロジェクト（または My PC）の「TM」を押すと、チームを始める画面が開きます。ここで、リーダーを Claude Code（ターミナル）にするか GPT（dsh のタスク）にするか、子に使うモデル、同時に動かせる子の数をそのチーム用に選び、「始める」でリーダーが起動します。子に使う GPT・Claude・Claude（API）・DeepSeek は、初期設定ではすべてオフです。初めてのときは、使うものをオンにしてから始めます（少なくとも一つをオンにすると「始める」を押せます）。2 回目からは前回のチームで選んだ値が入っているので、同じでよければそのまま始められます。リーダーに計画や指示を伝えると、リーダーが作業を分けて子のエージェントに任せ、終わった子から届く報告を確認して、合格（close）か手直し（send）かを決めます。

- **料金と実行方式:** Claude Code のリーダーと子は、この PC の Claude Code が通常使う認証と料金体系を引き継ぎます。本人のサブスクリプションだけでなく、本人の API キー（環境変数・設定・`apiKeyHelper`）やクラウド（Bedrock・Vertex・Foundry）も対象です。サブスクリプション専用にするための環境変数の除去や、API・クラウド認証の拒否はしません。Agent Desk に登録した API キーを Claude Code に自動で渡す方式ではありません。GPT のリーダーと子は dsh のタスクとして ChatGPT サブスクリプションで動きます。DeepSeek の子は dsh と登録済みの DeepSeek API キーを使う従量課金です。
- **自動処理には Claude（API）を推奨:** 自動で進むチーム作業には、Anthropic の API キーで動く dsh の「Claude（API）」の子を明示的に選ぶことを推奨します。Claude Code とは別の実行方式・会話履歴で、同じ会話への切り替えではありません。初期設定ではオフで、キーを登録して使うものを自分でオンにします。API・クラウドは従量課金で、並列実行や長いターンは料金が大きくなることがあります。利用前にプロバイダーの Console で支出上限などの管理を設定してください。**Agent Desk は米ドル建ての厳密な支出上限（ハードキャップ）を強制しません。** クレジットの有無や適用範囲は各プロバイダーの最新のプラン条件を確認してください。
- **Claude Code の認証・課金確認:** チーム開始画面と「このチームの設定」で、`claude auth status` による認証状態を確認できます。これはモデルを呼び出さない確認で、画面にはトークンやメールアドレスなどを除いた認証方式の説明だけを返します。Claude Code を使うには、表示された課金経路についての明示的な確認が必要です。確認は認証方式ごとで、同じ方式ならほかのチーム・フォルダでは聞き直しません。保存するのは確認した認証方式と同意の記録で、トークンやアカウント情報ではありません。リーダーと子の CLI プロセスを起動・再開するたび、および子の各ターンの前に再確認し、認証方式が変わっていたら再同意が必要です。認証方式が不明の場合は、通常の課金確認に加えて「課金経路を確認できないリスク」への別の明示的な同意が必要です。ログアウト状態では起動できません。このチーム用の確認は、通常の CL タスクには追加しません。
- **既存のチーム:** 保存済みの有効・無効、モデルの選択、会話履歴は維持します。Claude Code を Claude（API）に移行したり、自動でオンにしたり、認証失敗・利用上限などを理由に別経路へ自動で切り替えたりしません。既存チームも Claude Code の次の起動・再開・子ターンには必要な課金確認を行います。GPT のリーダーが Claude のサブエージェント（`subagent_claude`、API の従量課金）を使い始めたら、Agent Desk がその作業を止めてリーダーに知らせます。Claude（API）の子を使うよう、リーダーに伝えます。
- **モデルの選び方:** リーダーが選ぶのは枠（低・中）と GPT / Claude / Claude（API） / DeepSeek だけです。どの枠でどのモデルを動かすかは、チームを始める画面で決めます。GPT・Claude・Claude（API）・DeepSeek は、初期設定ではすべてオフです。使うものだけをオンにします（チームを始めるにも、動いているチームの設定を保存するにも、少なくとも一つはオンにしておきます）。オンにしたものは、低枠・中枠もそれぞれオフにできます（オンにしたものごとに、少なくとも一方の枠はオンのまま）。オフの枠はリーダーに使わないよう伝えます。同時に動かせる子の数（1〜12、close した子は数えない）もここで決めます。設定はチームごとに保存され、別のチームの設定には影響しません。
- **途中での変更:** 動いているチームでも、チームパネルの「このチームの設定」から、子に使うモデルと同時に動かせる子の数を変えられます。変えた内容はリーダーに伝わり、次に作る子から使われます（すでに動いている子はそのままのモデルで続けます）。リーダーを Claude と GPT で入れ替えることはできません。そのときは新しいチームを始めてください。
- **子はサブエージェントを使わない:** 子は自分で作業し、サブエージェントを起動しません。チームの人数が設定どおりに保たれ、動いているものがすべてチームパネルに出ます。並べて進めたい作業は、リーダーが子を増やして分けます。GPT・Claude（API）・DeepSeek の子は、サブエージェントのツール（`subagent`・`subagent_fork`・`subagent_gpt`・`subagent_claude` など）を外した子専用の dsh（`dsh --patch` で重ねる `team-child.patch.yml`）で動きます。子の心得（質問しない・自分の範囲だけ変える・報告の形など）も、この子専用の dsh がシステムプロンプトに入れるので（`server/team-child-plugin.js`）、長い作業で会話が要約されても消えません。Claude の子は `--disallowedTools` で、サブエージェント（Task）や、ほかのエージェントを動かすツール（Workflow・SendMessage・RemoteTrigger・CronCreate など）を使えなくしています。万一、子がサブエージェントを始めたときは、Agent Desk がその作業を止めてリーダーに知らせます。リーダーは自分のサブエージェントを使えます。
- **Claude の子の動かし方:** Claude の子は画面なしの Claude Code（`claude -p --output-format stream-json`）で動きます。1回の依頼ごとに Claude Code を起動し、同じ会話を再開します。作業中も Claude Code への入力は開けたままにして、あとから送るメッセージ（あなたの「割り込む」と、リーダーの `send`）を同じ依頼に渡します。Claude Code は次のステップでそれを読み、ステップが残っていなければ直後の続きの依頼として処理します。作業の終わり・返答・ツールの実行は Claude Code 自身の出力から読むので、フックや画面の読み取りに頼りません。Claude のリーダーはあなたが話しかける相手なので、これまでどおりターミナルの Claude Code です。リーダーの作業の終わりを知らせるフックが届かなかったときに備えて、報告が待っている間はリーダーの会話記録も確かめます。
- **報告の届き方:** 子が作業を終えると、その報告がリーダーの会話に自動で入力されます。報告は終わった順に届き、リーダーが作業中の間や、誰かが入力欄に書いている間は待ちます。待っている間に届いた報告は、次の 1 ターンでまとめて渡すので、報告の数だけリーダーのターンが増えることはありません（「設定 → エージェントチーム」の「報告をまとめて渡す」をオフにすると、1件ずつ届きます）。待っている間、リーダーは何もせず眠っているので、利用上限を使いません。長い報告は先頭だけを渡し、全文はリーダーが `read_report` で読みます。あなたが子に直接メッセージを送ったときも、その返答を「追加の報告」としてリーダーに届けます（close した子は除きます）。
- **同じ子への再依頼:** 手直しや、あとからの追加作業（2回目の見直しなど）は、リーダーが `send` で同じ子に送ります。子はそれまでの会話を覚えています。close した子にも、会話を引き継いで渡します。それまでの会話がほとんど要らない作業は、リーダーが `send` に `fresh: true` を付けて、子を新しい会話で始めさせます（前の会話は消えます。作業中の子には使えません）。
- **一時的なエラー:** 子のターンが、モデルのサービスの混雑・障害や通信の切断で止まったときは、リーダーに知らせる前に、1 分後に Agent Desk が 1 回だけ自動で再開します（dsh と Claude Code は、それぞれのリクエストをすでに再試行しています）。再開してもまた止まったとき、または利用上限・課金・認証など、すぐにまた失敗するエラーのときは、これまでどおりリーダーに届きます。待っている間に「全停止」を押すと、再開せずに止まります。
- **報告の中身:** 子は報告の前に、テスト・ビルド・実行・目視など、その作業でできる方法で結果を確かめ、何をどう確かめたかを報告に書きます。リーダーはそれを見て、どこまで自分で確かめるかを決めます。
- **子のツールを絞る:** 「設定 → エージェントチーム」の「子のツールを絞る」をオンにすると、次に始めるチームから、子はブラウザ・画面操作・画像生成のツールなし（Claude の子は、あなたが Claude Code に追加したものも含めて MCP サーバーなし）で始まります。子のターンごとに読み込むツールの説明が減ります。それらが要る子には、リーダーが `spawn` に `tools: true` を付けて渡します。初期設定はオフです。
- **承認:** 子はいつも承認なしで動きます（GPT はフルアクセス、Claude は `bypassPermissions`）。Claude の子では、それでも確認が要る操作は実行せずに飛ばし、報告に「承認が必要なため実行されなかった操作」として並べます。リーダーがその内容を見て判断します。GPT や DeepSeek の子が承認を待って止まったときは、まずリーダーに判断を求めます。リーダーにも決められないときはリーダーがあなたに確認を求め（通知が出ます）、14 分たってもリーダーが決めないときもあなたに知らせます。チームのパネルから直接「許可」「拒否」を押すこともできます。リーダーも承認なしで動かすかどうかは「設定 → エージェントチーム」で選べます。
- **画面:** リーダーには「TM」の印が付きます。子のタスクはサイドバーには出さず、リーダーの右側の「チーム」パネルに、名前・業務・モデル・状態を並べます。押すとその子の作業を開きます。Claude の子の画面では、作業の記録を読めるほか、子に直接メッセージを送ったり、作業を止めたりできます（どちらもリーダーに伝わります）。作業中に送ったメッセージは入力欄の上に予約として並び、作業が終わると自動で送られます。「割り込む」を押すと、終わりを待たずに今すぐ渡します（タスクの画面と同じです）。「図を開く」で、リーダーを上に、子を下に並べた構成図を表示します。作業中の子は光り、待機中や完了した子は薄く表示されます。
- **ツールの読み込み:** 子を動かすためのツール（MCP サーバー `server/team-mcp.js`）は、チームのリーダーにだけ渡します（Claude Code には `--mcp-config` で、GPT のリーダーにはその dsh のタスクの MCP サーバーとして）。GPT のリーダーへの指示文は、この MCP サーバーの instructions としてシステムプロンプトに入るので、会話が要約されても消えません。通常のタスクや CL のタスクには、ツールも指示文も加わりません。
- **GPT のリーダー:** 報告は、リーダーのタスクの作業が終わってからメッセージとして届けます。リーダーのモデルを決めていないときは GPT の中枠のモデルを使います。ChatGPT にサインインしている必要があります。
- **削除:** リーダーを削除すると、子のタスクも一緒に削除します。子だけを削除すると、その子はチームから外れます。
- **変更を戻す:** チームの子のタスクでは「変更を戻す」の保存をしません（同じフォルダで複数の子が同時に作業するため）。
