# エージェントチーム

[← README に戻る](../README.md)

サイドバーのプロジェクト（または My PC）の「TM」から、リーダーをモデルピッカーから選び、子のモデルと同時に動かせる子の数を選んでチームを始めます。子のモデルは低中モードでプロバイダーごとに低枠・中枠を設定するか、自由モードでモデルピッカーから最大12個を選べます。初めては子のモデルを自分で選びます。2回目からは前回の選択が入り、標準で開くモードは「設定 → エージェントチーム」で切り替えられます。リーダーは作業を子に任せ、報告を確認して合格（close）か手直し（send）を決めます。

- **料金と実行方式:** Claude Code のリーダーと子は、この PC の Claude Code が通常使う認証と料金体系を引き継ぎます。本人のサブスクリプションだけでなく、本人の API キー（環境変数・設定・`apiKeyHelper`）やクラウド（Bedrock・Vertex・Foundry）も対象です。サブスクリプション専用にするための環境変数の除去や、API・クラウド認証の拒否はしません。Agent Desk に登録した API キーを Claude Code に自動で渡す方式ではありません。GPT のリーダーと子は dsh のタスクとして ChatGPT サブスクリプションで動きます。Claude（API）と DeepSeek のリーダー・子は、dsh と登録済みの API キーを使う従量課金です。OpenCode Go のリーダー・子は、登録済みの API キーを使い、OpenCode Go の利用上限（5時間・週・月）の範囲で動きます。ローカル LLM は登録したサーバーを使います。
- **自動処理には Claude（API）を推奨:** 自動で進むチーム作業には、Anthropic の API キーで動く dsh の「Claude（API）」の子を明示的に選ぶことを推奨します。Claude Code とは別の実行方式・会話履歴で、同じ会話への切り替えではありません。初期設定ではオフで、キーを登録して使うものを自分でオンにします。API・クラウドは従量課金で、並列実行や長いターンは料金が大きくなることがあります。利用前にプロバイダーの Console で支出上限などの管理を設定してください。**Agent Desk は米ドル建ての厳密な支出上限（ハードキャップ）を強制しません。** クレジットの有無や適用範囲は各プロバイダーの最新のプラン条件を確認してください。
- **Claude Code の認証・課金確認:** チーム開始画面と「このチームの設定」で、`claude auth status` による認証状態を確認できます。これはモデルを呼び出さない確認で、画面にはトークンやメールアドレスなどを除いた認証方式の説明だけを返します。Claude Code を使うには、表示された課金経路についての明示的な確認が必要です。確認は認証方式ごとで、同じ方式ならほかのチーム・フォルダでは聞き直しません。保存するのは確認した認証方式と同意の記録で、トークンやアカウント情報ではありません。リーダーと子の CLI プロセスを起動・再開するたび、および子の各ターンの前に再確認し、認証方式が変わっていたら再同意が必要です。認証方式が不明の場合は、通常の課金確認に加えて「課金経路を確認できないリスク」への別の明示的な同意が必要です。ログアウト状態では起動できません。このチーム用の確認は、通常の CL タスクには追加しません。
- **既存のチーム:** 保存済みの有効・無効、モデルの選択、会話履歴は維持します。Claude Code を Claude（API）に移行したり、自動でオンにしたり、認証失敗・利用上限などを理由に別経路へ自動で切り替えたりしません。既存チームも Claude Code の次の起動・再開・子ターンには必要な課金確認を行います。dsh のリーダーが Claude のサブエージェント（`subagent_claude`、API の従量課金）を使い始めたら、Agent Desk がその作業を止めてリーダーに知らせます。Claude（API）の子を使うよう、リーダーに伝えます。
- **モデルの選び方:** 低中モードでは、GPT・Claude Code・Claude（API）・DeepSeek・OpenCode Go・ローカル LLM ごとに低枠・中枠を設定し、使わない枠をオフにできます。自由モードでは「モデルを追加」からモデルと推論レベルを選びます（最大12個、同じプロバイダーとモデルの重複は不可）。既存の設定・チームは低中モードのまま引き継がれます。モードごとの選択は保持され、チーム開始時と開始後の設定で切り替えられます。指定がなければ、アプリは子の起動回数が少ないモデルから均等に選びます。利用回数はそのチームの子を基準にし、同じ子への再依頼は新規起動として数えません。同時に動かせる子の上限（1〜12）はモデルの個数とは別です。
- **方針とプレイブック:** 「設定 → エージェントチーム」に、TMのリーダーだけが読む文章を書いておけます。ECO・AB・通常のタスク・子には渡しません。**方針**は複数保存し、チーム開始時に一つ選びます（「なし」も選べます）。全文はリーダーのシステムプロンプトに入り、会話が要約されても消えません。起動時に読むため、変更は次に起動したときから使われます。方針は 2,000 文字までです。「方針作成指示文をコピー」から、モデルの公式情報やベンチマークを調べて使い分け方針を作るための依頼文をコピーし、AIに渡せます。**プレイブック**は名前・使う場面・本文の組です。リーダーには名前と使う場面だけを渡し、作業が合うときに `playbook` ツールで本文を開きます。本文の変更は次に開いたとき、一覧の変更はリーダーの次の起動から反映されます。ツールは起動時にプレイブックがあるときだけ渡します。方針やプレイブックがモデル・枠・プロバイダーを指定した場合は均等利用より優先されますが、選ばれていないモデルやオフの枠は使えません。
- **PTC:** 開始画面の「PTC ON／OFF」で、dshで動くリーダーと子の実行方式をまとめて選べます（初期オフ）。開始後はチームパネルから、親子が待機中のときに切り替えられます。設定はチーム単位で保存され、既存の子の次の送信・再開にも反映します。Claude Codeで動く担当には適用しません。ecoでも同じ切り替えを使い、調査担当の読み取り専用と検証・差し戻し・親の判定は維持します。
- **途中での変更:** 動いているチームでも、チームパネルの「このチームの設定」から、子に使うモデルと同時に動かせる子の数を変えられます。変えた内容はリーダーに伝わり、次に作る子から使われます（すでに動いている子はそのままのモデルで続けます）。「このチームの設定」ではリーダーを入れ替えられません。dsh のリーダーは通常のタスク画面からモデルを変更できますが、Claude Code と dsh の実行方式を入れ替えるには新しいチームを始めてください。
- **子はサブエージェントを使わない:** 子は自分で作業し、サブエージェントを起動しません。チームの人数が設定どおりに保たれ、動いているものがすべてチームパネルに出ます。並べて進めたい作業は、リーダーが子を増やして分けます。GPT・Claude（API）・DeepSeek・OpenCode Go の子は、サブエージェントのツール（`subagent`・`subagent_fork`・`subagent_gpt`・`subagent_claude` など）を外した子専用の dsh（`dsh --patch` で重ねる `team-child.patch.yml`）で動きます。子の心得（質問しない・自分の範囲だけ変える・報告の形など）も、この子専用の dsh がシステムプロンプトに入れるので（`server/team-child-plugin.js`）、長い作業で会話が要約されても消えません。Claude の子は `--disallowedTools` で、サブエージェント（Task）や、ほかのエージェントを動かすツール（Workflow・SendMessage・RemoteTrigger・CronCreate など）を使えなくしています。万一、子がサブエージェントを始めたときは、Agent Desk がその作業を止めてリーダーに知らせます。リーダーは自分のサブエージェントを使えます。
- **Claude の子の動かし方:** Claude の子は画面なしの Claude Code（`claude -p --output-format stream-json`）で動きます。1回の依頼ごとに Claude Code を起動し、同じ会話を再開します。作業中も Claude Code への入力は開けたままにして、あとから送るメッセージ（あなたの「割り込む」と、リーダーの `send`）を同じ依頼に渡します。Claude Code は次のステップでそれを読み、ステップが残っていなければ直後の続きの依頼として処理します。子が長いコマンドをバックグラウンド（`run_in_background` や Monitor）で動かしたままターンを終えたときは、入力を開けたまま待ちます。コマンドが終わると Claude Code が自分で続きを始め、バックグラウンドに何も残っていないときの最後の返答だけが、リーダーへの報告になります（「待っています」のような途中の返答は届きません）。待つのは最長 2 時間で、それを過ぎたら待つのをやめ、止まった作業を報告に書きます。作業の終わり・返答・ツールの実行は Claude Code 自身の出力から読むので、フックや画面の読み取りに頼りません。Claude Code のリーダーはあなたが話しかける相手なので、ターミナルの Claude Code です。リーダーの作業の終わりを知らせるフックが届かなかったときに備えて、報告が待っている間はリーダーの会話記録も確かめます。
- **報告の届き方:** 子が作業を終えると、その報告がリーダーの会話に自動で入力されます。報告は終わった順に届き、リーダーが作業中の間や、誰かが入力欄に書いている間は待ちます。待っている間に届いた報告は、次の 1 ターンでまとめて渡します。ほかの子がまだ作業中なら、報告は最長 30 秒、続く報告を待ってから一緒に渡すので、近い時間に終わった子の報告が 1 件ずつ別のターンになることはありません（承認待ちは待たずに届きます）。「設定 → エージェントチーム」の「報告をまとめて渡す」をオフにすると、1件ずつすぐ届きます。待っている間、リーダーは何もせず眠っているので、利用上限を使いません。長い報告は先頭だけを渡し、全文はリーダーが `read_report` で読みます。あなたが子に直接メッセージを送ったときも、その返答を「追加の報告」としてリーダーに届けます（close した子は除きます）。
- **親の待機と並行作業:** dshの親はTM・eco共通で、子への委託後、報告待ちだけの自動goal roundを繰り返しません。現在のターン内では独立した仕事を進められます。さらに自動継続が必要なら親が `wait({waiting:false})`、報告待ちに戻るなら `wait()` を使います。未配送の報告・承認要求・ユーザー判断・全停止が優先され、目標と残り回数は保持します。質問への入力は、新しいメッセージが受理されたときだけ回答扱いにします。拒否された送信や重複再送、子の報告では質問待ちを解除しません。質問を閉じる操作は回答・承認ではなく、そのことを親に知らせます。
- **同じ子への再依頼:** 手直しや、あとからの追加作業（2回目の見直しなど）は、リーダーが `send` で同じ子に送ります。子はそれまでの会話を覚えています。close した子にも、会話を引き継いで渡します。それまでの会話がほとんど要らない作業は、リーダーが `send` に `fresh: true` を付けて、子を新しい会話で始めさせます（前の会話は消えます。作業中の子には使えません）。
- **一時的なエラー:** 子のターンが、モデルのサービスの混雑・障害や通信の切断で止まったときは、リーダーに知らせる前に、1 分後に Agent Desk が 1 回だけ自動で再開します（dsh と Claude Code は、それぞれのリクエストをすでに再試行しています）。再開してもまた止まったとき、または利用上限・課金・認証など、すぐにまた失敗するエラーのときは、これまでどおりリーダーに届きます。待っている間に「全停止」を押すと、再開せずに止まります。
- **報告の中身:** 子は報告の前に、テスト・ビルド・実行・目視など、その作業でできる方法で結果を確かめ、何をどう確かめたかを報告に書きます。リーダーはそれを見て、どこまで自分で確かめるかを決めます。
- **子のツールを絞る:** 「設定 → エージェントチーム」の「子のツールを絞る」をオンにすると、次に始めるチームから、子はブラウザ・画面操作・画像生成のツールなし（Claude の子は、あなたが Claude Code に追加したものも含めて MCP サーバーなし）で始まります。子のターンごとに読み込むツールの説明が減ります。それらが要る子には、リーダーが `spawn` に `tools: true` を付けて渡します。初期設定はオフです。オフのときや `tools: true` の子では、Claude の子にも Claude in Chrome を渡します（画面なしの Claude Code は `--chrome` なしでは使いません）。
- **承認:** 子はいつも承認なしで動きます（GPT はフルアクセス、Claude は `bypassPermissions`）。Claude の子では、それでも確認が要る操作は実行せずに飛ばし、報告に「承認が必要なため実行されなかった操作」として並べます。リーダーがその内容を見て判断します。GPT・DeepSeek・OpenCode Go の子が承認を待って止まったときは、まずリーダーに判断を求めます。リーダーにも決められないときはリーダーがあなたに確認を求め（通知が出ます）、14 分たってもリーダーが決めないときもあなたに知らせます。チームのパネルから直接「許可」「拒否」を押すこともできます。リーダーも承認なしで動かすかどうかは「設定 → エージェントチーム」で選べます。
- **画面:** リーダーには「TM」の印が付きます。子のタスクはサイドバーには出さず、リーダーの右側の「チーム」パネルに、名前・業務・モデル・状態を並べます。押すとその子の作業を開きます。Claude の子の画面では、作業の記録を読めるほか、子に直接メッセージを送ったり、作業を止めたりできます（どちらもリーダーに伝わります）。作業中に送ったメッセージは入力欄の上に予約として並び、作業が終わると自動で送られます。「割り込む」を押すと、終わりを待たずに今すぐ渡します（タスクの画面と同じです）。「図を開く」で、リーダーを上に、子を下に並べた構成図を表示します。作業中の子は光り、待機中や完了した子は薄く表示されます。
- **ツールの読み込み:** 子を動かすためのツール（MCP サーバー `server/team-mcp.js`）は、チームのリーダーにだけ渡します（Claude Code には `--mcp-config` で、dsh のリーダーにはそのタスクの MCP サーバーとして）。dsh のリーダーへの指示文は、この MCP サーバーの instructions としてシステムプロンプトに入るので、会話が要約されても消えません。通常のタスクや CL のタスクには、ツールも指示文も加わりません。
- **dsh のリーダー:** 報告は、リーダーのタスクの作業が終わってからメッセージとして届けます。設定・モデル一覧の更新による実行環境の入れ替えと重なった場合は、終了を待って新しい接続で同じ会話の再開を試みます（通常方式・PTC共通）。再開できない場合は、これまでのやり取りを要約して新しい会話に引き継ぎます。報告やモデル要求を重複送信する方式ではありません。以前の設定で GPT リーダーのモデルが未設定の場合は、GPT の中枠・低枠・自由モードで選択した GPT モデルの順に使います。モデルによってツールの利用やチームを率いる能力は異なります。
- **削除:** リーダーを削除すると、子のタスクも一緒に削除します。子だけを削除すると、その子はチームから外れます。
- **変更を戻す:** チームの子のタスクでは「変更を戻す」の保存をしません（同じフォルダで複数の子が同時に作業するため）。

## モデル選択の設計

均等利用を確実にするため、リーダーが選択を省略したときはアプリが、そのチームで起動数の少ないモデルを選びます。リーダーへの指示だけで均等利用を求める方法と違い、並列起動や再起動後も偏りを抑えられます。方針やプレイブックで指定されたモデルは明示的に渡せますが、ユーザーが選んだ範囲を超えたり、別の課金経路へ切り替えたりはしません。

リーダーはモデルとプロバイダーを一緒に保存します。Claude Code と GPT の既存設定はそのまま読み、追加した dsh モデルは選んだ経路を明示的に保存します。表示名から実行経路を推測して切り替える方法は使いません。
