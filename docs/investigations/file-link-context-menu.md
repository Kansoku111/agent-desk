# 回答リンクのExplorer表示・前面化

2026-10-26 / Windows。最初の依頼では調査だけを行い、その後の修正依頼を受けて、Explorer表示と起動結果の通知を修正しました。

## 修正内容

- `server/open-front.ps1` の `explorer.exe /select,...` 起動を、Windows標準の `SHOpenFolderAndSelectItems` に変更しました。フォルダーと選択対象をPIDLで渡すため、日本語・空白・カンマ・引用符・`&`・角括弧をコマンド文字列として解釈しません。
- ウィンドウの新旧ではなく、Shell.Applicationのフォルダービューと選択された項目が要求に一致するExplorerを特定します。既存ウィンドウが再利用されても、最小化を解除して前面化します。関係のない新規ウィンドウを前面化する処理は削除しました。
- Explorerの対象ビュー・選択と実際の前面HWNDを確認してから成功とします。表示待ちや前面化が成功しなければ終了コード1とエラーを返します。Windowsの前面化制限を無条件に解除するものではなく、拒否された場合はその旨を通知します。
- `server/system.js` はWindowsのSTA PowerShellヘルパーを待ち、標準エラー・終了コード・15秒のタイムアウトを日本語のエラーにして返します。パスは専用環境変数で渡します。macOS/Linuxの既存の非同期起動方法は変更していません。
- `server/rpc-handlers-workspaces.js` の `file.open` も完了を待つため、失敗は既存の画面のエラー通知へ届きます。
- 通常ファイルの「開く」は既定の関連付けから起動し、起動エラーを返します。実行ファイル・スクリプトは引き続き直接実行せずExplorer表示へ切り替えます。フォルダーの「開く」はそのフォルダーを表示し、「エクスプローラーで表示」は親の中で選択します。ドライブのルートはそのまま開きます。

## 原因と確認結果

以前の実装には次の2つの問題がありました。

1. 新しくできたHWNDだけを前面化対象にしており、既存Explorerを再利用した場合を扱えませんでした。
2. PowerShellのエラーを抑制し、サーバー側でも起動結果を捨てて成功扱いにしていました。旧ヘルパーでは、起動だけを診断用に失敗させても終了コード0になることを確認しています。

修正後はWindows実機で次を確認しました。

- 実際の `file.open` ハンドラー → Nodeの起動処理 → PowerShell → Windows APIの経路でREADMEを選択し、完了後の前面HWNDが対象Explorerと一致すること。
- 同じExplorerを最小化後、別ファイルへの表示で**同じHWND**を再利用し、最小化解除・新しい選択・前面化がすべて成功すること。
- 日本語・空白・`&`・角括弧・引用符を含む一時フォルダーとファイルで、対象の選択と既存ウィンドウの復元が成功すること。
- フォルダー自体を開く操作と、親の中でフォルダーを選択する操作。

調査で開いたウィンドウだけをHWND・場所で照合して閉じ、一時フォルダーも削除しています。ユーザーの会話や作業ファイルは変更していません。

## 回帰テスト

`test/file-open.test.js` で次を検証します。

- Windowsの起動完了待ち、STA指定、特殊文字を含むパスの受け渡し、起動失敗・タイムアウトの伝播。
- RPCの完了待ち・エラー伝播と、実行ファイルを直接実行しない既存ガード。
- 実際のPowerShellヘルパーの分岐・ビュー照合・選択確認。OS操作だけをモックし、既存ビューを選び、無関係なビューを無視すること。
- ファイル・フォルダー・ドライブルート、および表示未完了・前面化拒否・ネイティブAPI失敗・関連付け起動失敗の終了コード1。
