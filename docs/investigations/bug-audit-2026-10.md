# 不具合調査と採否（2026-10）

12人を4モデル枠に3人ずつ割り振り、調査と実装を分離した。リーダーが呼び出し経路・実害・再現方法を確認し、修正を強く勧められる14件を採用した。見た目の好みや未検証の防御策は含めていない。

## 採用した不具合

|番号|問題|修正・主な回帰検証|
|---|---|---|
|1|配布ZIP・単体アップデーターに必須の `shared/` がなく、展開先で起動できない|3つの同梱・更新リストを修正。`release-inputs.test.js` が一時コピーを実際に梱包・展開して共有importを確認|
|2|静的ファイル・Vite設定・共有コードだけの変更でUIを自動ビルドしない|`ensure-build.mjs` の入力を補完。入力ごとにビルドの有無を検証|
|3|共有JSだけの変更で実行コードの指紋が変わらず、旧インスタンスを使い続ける|`code-stamp.js` に共有JSを追加。共有コードだけの変更を検証|
|4|旧インスタンスの終了を待つ後継が、旧プロセス消滅時に起動せず終了する|既存のOSロック取得へ進む。`single-instance-successor.test.js` で引継ぎと二重起動防止を検証|
|5|初回にブラウザツールを並行起動すると別ポートを保存し、一部セッションが接続できない|ロック内で再読込・ポート選択・atomic保存。`chrome-state.test.js` が4プロセスで一致を確認|
|6|無関係なOAuth callbackが正当なChatGPTログイン試行を消費する|GET・state一致を確認してから消費。不正要求後の正常完了、拒否、重複を `chatgpt-login-state.test.js` で検証|
|7|eco検証行の削除後の追加でIDが重複し、保存できない|未使用の `check-N` を生成。サーバーの重複拒否も維持|
|8|Claudeワークスペースの候補が後着すると、見えている候補を設定できない|表示値・有効状態・送信値を同じ選択から導出。候補1件の実UI操作も検証|
|9|サブエージェントの子への委託分がターン利用量から抜ける|同じログフォルダの親子関係をたどり、時間範囲内の子孫を重複なく集計|
|10|単価不明のAPI使用量を$0、または既知分だけで全額のように表示する|未算定件数を集計・移行し、タイル・モデル行・グラフで `—` / `≥` を表示。非課金・既知ゼロと区別|
|11|同じClaude端末への並行送信で本文が結合する|本文・Enter・必要な再試行を端末単位で直列化。別端末の並行性は維持|

|13|新規タスク作成の応答喪失後の再送で、同じ依頼を二重実行する|同じタブの再試行で安定した作成IDを使い、サーバーに作成・メッセージ受領を永続化。並行・再起動・削除後・保存失敗を検証|
|14|一時的なHTTP 429を無効な要求に分類し、再試行せず終了する|upstreamの `RATE_LIMIT` に戻す。実際のquota判定と再試行policyで、認証・恒久上限を再試行しないことも確認|

## 採用しなかった主な候補

- アップデーターの全引数が壊れるとの指摘は、PowerShellからの再現と実exeの引数解釈が違う誤検出だった。実 `ProcessStartInfo` 経路で正常と確認し、不採用。
- 復元記録の短い遅延保存窓、手編集で壊れた設定・資格情報、macOSの異常終了後のロックなどは、今回の通常利用での到達性・実害の根拠が足りないため保留。
- 未検証のID tokenを先に保存する案は採用せず、認証検証を維持した。
- ABの無効ボタン、チーム停止人数の文言、close直後の誤通知、空白入り画像パスの抽出は、今回の強い修正推奨の基準に達しないため変更しなかった。
- 使用履歴の重複応答・圧縮データ中のmagic番号については、実ログでの発生や再現入力の妥当性が不十分なため保留。

## 検証方法と範囲

- モデル通信・実ユーザーの設定変更・実アプリの更新や再起動は行わず、一時データ・模擬HTTP/PTY/モデル応答で検証した。
- UIは実コンポーネントと模擬RPCで操作した。`settings-bug-audit-ui.html` の `settingsAudit.run()`、`usage-pricing-ui.html` の `usagePricingTest.run()` を使い、料金表示は375px幅でも確認した。[実行方法](../development.md)。
- `npm test`、`npm run typecheck`、`npm run build`、`git diff --check` で最終確認する。詳細な調査用スクリプトと実行ログはローカルの `research/bug-audit/` に保存した（Git対象外）。

## 残る範囲

- 公開済みの旧ZIPはこのソース修正だけでは差し替わらない。修正を配布するには新しいリリース成果物の作成・公開が必要。今回、公開操作は行っていない。
- 削除済みログの旧料金キャッシュに、算定済み・未算定の内訳が残っていない場合は復元できない。
- 作成IDは同じタブ内の再試行を対象とする。削除済みタスクの作成IDは二重実行を防ぐため保持し、期限管理は追加していない。
