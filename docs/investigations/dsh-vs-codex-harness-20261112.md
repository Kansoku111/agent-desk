## 送っている内容の違い

| | dsh（PTCオン） | Codex 0.167.0（GPT-6系） |
| --- | --- | --- |
| モデルが直接呼ぶ道具 | `run_code` の1つ | `exec`、`wait`、質問、サブエージェント系 |
| プログラムの渡し方 | JSON の `code` 文字列 | 生の JavaScript（JSON で包まない custom ツール） |
| プログラムから呼ぶ道具 | `read`・`edit`・`write`・`grep`・`glob`・`pwsh`・ジョブ・todo・MCP など | `exec_command`（シェル）・`apply_patch`・`write_stdin`・`view_image`・Web・MCP |
| 基本の指示 | 28,330 文字（道具の型宣言を含む） | 17,793 文字（人格・報告の書き方・許可の取り方が大半） |
| 道具の宣言 | `run_code` 3,215 文字（型宣言は上の指示の中） | 36,045 文字 |
| 出力の上限 | 道具ごとの既定 | 呼び出しごとにモデルが `max_output_tokens` を指定 |

Codex も GPT-6 系では「プログラムを書いて道具を呼ぶ」方式です。dsh の PTC と考え方は同じで、違いは細部にあります。Codex の基本指示のうち作業の進め方は12行ほどで、効率に関わるのは「検索は `rg`」「独立した検索と読み取りは1回の `exec` にまとめる」の2点です。

## 長い作業での道具の使い方

同じ課題ではないため、傾向だけを見ます。

| | リクエスト | プログラム1回あたりの道具呼び出し | 道具の結果（文字数）中央値／9割点 | キャッシュ率 | 1リクエストあたり出力 |
| --- | --- | --- | --- | --- | --- |
| dsh Terra/xhigh（tagame-game、修正） | 53 | 4.28 | 1,530／23,773 | 97.6% | 589 |
| dsh Terra/xhigh（tagame-game、ブラウザ確認） | 61 | 1.63 | 863／11,978 | 96.3% | 131 |
| dsh Terra/xhigh（Agent Desk、機能追加） | 27 | 3.58 | 872／16,887 | 95.1% | 303 |
| Codex Terra/high（tagame-game、修正） | 89 | 1.05 | 486／5,880 | 98.4% | 326 |
| Codex Terra/xhigh（Agent Desk、調査と修正） | 26 | 2.16 | 3,069／30,645 | 95.2% | 243 |
| Codex Luna/xhigh（Agent Desk、リリース作業） | 150 | 1.01 | 1,586／4,524 | 98.7% | 253 |

- **まとめ方:** dsh は1回のプログラムに道具呼び出しを3〜4個入れています。Codex は道具呼び出しは1〜2個ですが、1つのシェルコマンドに `rg` や `Get-Content` を `;` でつないでまとめています。
- **出力の絞り方:** Codex のモデルは呼び出しごとに `max_output_tokens` を 1,000〜6,500 で指定していました。
- **待ち時間:** Codex は長いコマンドの完了を `write_stdin` の空打ちで待ち、89 リクエスト中 32、150 リクエスト中 97 が待つだけのリクエストでした（Windows では1回の待ちが最長30秒）。dsh はジョブとして待つので、ここは dsh が有利です。
- **編集:** Codex は `apply_patch`。dsh は `edit` で、1つの作業で 94 回呼んだ例がありました。

## 取り入れる候補（未検証の仮説）

効果はまだ測っていません。採用の前に同じ課題の組で測ります。

1. **プログラムを JSON で包まずに渡す。** dsh はプログラムを JSON 文字列で受け取るため、エスケープが二重になります。エスケープの多い課題で PTC オンの点数が半分になった件（[調査](gpt-siwc-regression-20261107.md)）と、PTC の構文エラーの原因と重なります。`run_code.data` はその回避策でした。SIWC と pi-ai が custom ツールを通せるかは未確認です。
2. **呼び出しごとの出力上限をモデルに選ばせる。** これまでの計測で、費用差の主因は道具の結果による文脈の増え方でした。
3. **`apply_patch` を有効にして比べる。** dsh 0.2.2-rc.1 に同じ形式の道具が入っていますが、Agent Desk のタスクでは有効にしていません。
4. **取り入れないもの:** シェルだけで読む方式（PowerShell の引用が増える）と、`write_stdin` での待ち方。

GPT が Codex の道具の形に合わせて訓練されているかは、ログからは分かりません。1 と 3 の計測がその確認にもなります。
